# 农客松作品墙与 Star 人气奖交付记录

本轮实现及本地验证已完成。用户已追加授权提交、推送任务分支并创建 PR；生产迁移、合并与上线不在当前授权范围。新增三表仅在隔离测试库验证。

- 工作区：独立的 `agri-wall-stars` 本地工作树。
- 分支：`codex/agri-wall-stars-20261015`，基于最新获取的 `origin/main` 建立。
- 原项目目录和其他工作区的未提交工作均保留。

## 已完成的体验

1. 赛事主页引导「免费发布项目 → 审核公开 → 绑定参赛队 → 正式提交」。完全在 ANS 外制作的项目可以参赛，参赛建档不调用模型、不扣点。
2. 项目广场新增农客松作品墙分类及独立入口。公开介绍与私密项目事实分开；绑定、重试、公开版本同步和正式提交均有服务端校验。
3. 作品卡分开呈现累计 Star 与本届有效 Star，包含搜索、加载、空态、错误重试、计票反馈、中英文及手机布局。
4. 获授权的赛事工作人员可配置统一北京时间计票窗口。开票锁定窗口和新增队伍绑定，避免候选作品进入时间不同；历史 Star 必须在窗口内主动确认才算本届有效票。
5. 同一账号对同一作品最多一张有效票；发布者、该队活跃成员、正式名单成员及 flagged/deleted 账号不计入。人气奖不替代评审评分或晋级资格。
6. 截止结果持久封存；之后取消普通 Star、队员或账号状态变化不会改写已封存结果。同票第一共同获奖，全零不授奖。撤回隐藏公开作品，保留提交和奖项历史。
7. 新增作品绑定、计票届次和有效票三张表，保留原表和数据；修复并发绑定、重复投票、跨账号请求和截止边界等问题。

## 使用边界

- 当前投票约束按 ANS 账号执行，不等于一人一票，也不能证明杜绝多账号刷票；未新增实名或认证流程。
- 所有参赛队应在统一开票前完成作品审核及绑定。已开票窗口不能修改，新候选绑定被拒绝；组织者需先确认真实届次及日期再启用。
- 新表迁移包含数据库约束及截止封存触发器，生产应用必须按正式发布流程另行授权。真实届次规则、生产迁移和线上效果尚未验证。
- 本轮无新增依赖。参考了 giscus 的公开 reaction 交互方法（MIT），未复制代码，保留 ANS 原有按目标状态写入 Star 的接口。
