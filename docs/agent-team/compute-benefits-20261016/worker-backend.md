# Backend implementation — compute benefits, 2026-10-16

Scope: versioned onboarding questionnaire and personal agri signup review, isolated official-USD grant ledger, account-owner API, admin USERS_MANAGE review and gateway reserve/completion helpers. No real grants, upstream calls, commits or production changes.

- Onboarding is one grant per account/campaign/kind: 1000 USD DeepSeek. Agri approval is three fixed grants: Terra 300, Astra/Sol shared 200, Opus 100. No generic points or wallet mutation.
- Every grant is immutable in origin, amount, model whitelist and exact 720-hour lifetime. All times originate in PostgreSQL. Submission/review/grants are transactional, reviews use expected revision and immutable events.
- Agri personal signup derives the configured competition ID server-side and uses the managed registration window before account locks, then rechecks the deadline before a write. Approval binds the same immutable edition; it may happen after registration closes. It does not approve a team competition entry or a competition artifact.
- User and admin reads/writes recheck active accounts; admin routes and service independently enforce USERS_MANAGE. Browser writes require same origin, JSON and actor binding. Private responses are no-store; no answers or DB diagnostics are logged.
- Financial helpers use account -> grant -> reservation locks. A matching exhausted/expired model pool rejects instead of silently charging paid funds. Existing liabilities may complete after feature disable or account restriction. Completion caps user debit at the held amount; excess is recorded as platform-covered USD.
- Forward SQL migration `20261016180000_compute_benefits` adds strict non-null terminal checks, model/amount policy checks, immutable fields, source proof guards, deferred ledger conservation and bidirectional gateway quote binding. Settled gift actual USD must match immutable VERIFIED raw quota after undoing the receipt multiplier. Release requires explicit rejection or audited admin waiver.
- `ANS_COMPUTE_BENEFITS_ENABLED=1` gates new grants, reads and reservations; off state never reads new tables. Completion is deliberately still available for an existing hold.

Validation: focused source ESLint passed. Unit test execution initially encountered sandbox spawn EPERM and its escalation waited without running; that wait was aborted. Root now owns the unified test/type/real-PG verification. `src/__tests__/lib/compute-benefits.test.ts` covers fixed policy, strict input, owner/status/amount guards, duplicate reservations, cap/refund semantics, shared source behavior, review race, configured edition and registration timing/error mapping. `scripts/fixtures/compute-benefits.sql` supplies synthetic PostgreSQL migration/evidence tests; no real user data is copied. Actual test and DB results must be taken from root's receipts, not inferred from fixture existence.

Remaining limits: Terra upstream credentials absent; channel/price/protocol activation remains independently gated. Opus activation remains governed by root's prior protocol/evidence gates. No migration rollback SQL is offered that destroys gift ledgers: application rollback disables new issuance/reservations while preserving rows and completion/recovery support.
