## 问题

### REVIEW-001 / P2：统一计费模式下通用运行表单仍显示固定积分

位置：`src/app/workflows/[slug]/page.tsx` 通用 `WorkflowRunForm` 的 `estimatedCost={cost}`，以及 `src/components/workflows/workflow-run-form.tsx` 对 `learning.billingExplanation` / `learning.billingRun` 的调用。

复现条件：`ANS_UNIFIED_POINTS_ENABLED=1`、`ANS_APIC_BILLING_ENABLED=1`，公开合法的非 recipe 工作流；登录后打开详情。

实际：新增页正文显示按实际模型计费，但运行表单仍显示按节点数量算出的固定「最多预占 N 积分」及对应按钮。服务端 `createWorkflowRun` 在统一计费模式创建任务时 `costPoints=0`，模型调用按实际请求计费。表单的固定上限与真实契约不一致。

建议：给通用表单明确的计费模式或可空费用，统一计费模式使用按实际算力费用确认文案。保留非统一模式的真实固定费用，不改支付与运行 API。

状态：已修复并于 2026-10-14 复查关闭。

### REVIEW-002 / P2：通用入口的版本说明容易被理解为锁定当前页面版本

位置：`src/app/workflows/[slug]/page.tsx` 的固定版本标记和条件说明，`messages/product/{zh,en}.json` 的 `workflowDetail.immutableVersion` / `versionNotice`。

复现条件：打开合法非 recipe 工作流 v1 页面后，管理员发布 v2；用户未刷新便点击通用运行表单。

实际：表单 POST 仅含 `input` 与 `idempotencyKey`，接口读取点击时最新 `publishedVersion`，不会比较页面版本 v1，任务可能实际运行 v2。新增「固定发布版本 v1」及「执行绑定已发布的固定版本」没有说明通用入口启动时重新读取当前版本。Recipe / market 入口则有 expectedVersion 比较，二者不能共用锁定页面版本的承诺。

建议：不改 API 的前提下，将通用入口说明为页面展示版本、启动时读取最新发布版本，任务创建后固定；保留 recipe / market 严格版本校验的表述。

状态：已修复并于 2026-10-14 复查关闭。
