## 服务器配置

沿用 ANS 的鉴权、PostgreSQL、算力流水与 S3 依赖，不安装额外包。数据库迁移文件为 `prisma/migrations/20261013122000_visual_model_jobs_and_websites/migration.sql`；生产应用需单独授权。

| 配置 | 含义 |
| --- | --- |
| `ANS_TRIPO_ACCEPTING_JOBS` | 默认关闭；设为 `true` 才接受用户生成请求 |
| `ANS_TRIPO_PRICE_POINTS` | 经运营确认的 ANS 积分售价，六位小数；上游积分与 ANS 积分不等价 |
| `ANS_VISUAL_WORKER_KEY` | 至少 32 字符的随机密钥，服务器与本机一致 |
| `ANS_VISUAL_SIGNING_SECRET` | 至少 32 字符，用于短期模型访问授权 |
| `ANS_VISUAL_STORAGE_MODE` | 本机为 `local`；首版单服务器使用持久磁盘 `local`，多实例时切换 `s3` |
| `ANS_VISUAL_STORAGE_DIR` | `local` 模式的持久目录，应定期备份；线上挂载服务器持久磁盘，不使用容器临时盘 |
| `S3_BUCKET / S3_REGION / S3_ENDPOINT / S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY` | 线上存储配置，沿用项目现有 S3 方式 |
| `ANS_VISUAL_PUBLISH_ENABLED` | 默认关闭；托管配置完成后设为 `true` |
| `ANS_VISUAL_PUBLIC_ORIGIN` | 与 ANS 主站不同来源的作品网站域名，如 `https://portfolio.example.net` |
| `ANS_VISUAL_PUBLICATION_KEY` | 至少 32 字符；仅 ANS 与托管 Worker 持有 |

本机服务向公网 ANS 主动发送 HTTPS 请求，因此家中电脑不需要开放入站端口。电脑必须运行且联网。默认一次处理一个生成任务；每个用户最多有三个待完成或待核对任务。

## 本机启动

凭据已由用户保存于 `%LOCALAPPDATA%/ANS/credentials/tripo3d.credential.xml`，用同一 Windows 用户运行。DPAPI XML 只能在该 Windows 用户环境解密，不放进 Git 或托管服务器。

先将 Worker 配置存入 Windows 用户级环境变量：`ANS_WORKER_SERVER`、`ANS_VISUAL_WORKER_KEY`、`ANS_TRIPO_DOWNLOAD_HOSTS=tripo-data.rg1.data.tripo3d.com`。需要持续生成时另设 `ANS_TRIPO_ALLOW_SUBMISSIONS=true`，且 ANS 服务器接受任务开关与售价已配置。

```powershell
./scripts/visual-worker/start-local.ps1 -Mode preflight
./scripts/visual-worker/start-local.ps1 -Mode start
```

preflight 只登录和读模型配置；start 会按用户在 ANS 确认的任务上传图片并生成。不要在没有真实测试授权时启动提交模式。常驻运行可由 Windows 任务计划程序在登录时启动此脚本，失败后重启；启动目录指向本工作区，同一账号只启动一个实例。服务默认 journal 位于 `%LOCALAPPDATA%/ANS/tripo-journal`，只记录提交意图与任务 ID，不记录密码、token 或图片。

提交前取消可退积分。提交后保留结果并等待费用核对。若上游 POST 的响应丢失，进入 `NEEDS_REVIEW`，不会重新生成；若任务 ID 已保存，重启后继续查询原任务。最终保存结果允许相同文件重试，不会重复创建资产。上游失败和格式不支持的补偿由运营核对，不自动推断上游已退费。

## 自定义域名

使用 Cloudflare for SaaS 的 Custom Hostnames，并先按照官方说明准备 fallback origin 与 Worker 路由。普通 Worker custom domain 配置本身不能替代客户域名接入。实际 DNS 与证书配置需确认所用 Cloudflare 账户、套餐和域名后实施。

| 配置 | 含义 |
| --- | --- |
| `ANS_VISUAL_DOMAINS_ENABLED` | 默认关闭 |
| `CLOUDFLARE_SAAS_ZONE_ID` | SaaS zone 的 32 位 ID |
| `CLOUDFLARE_SAAS_TOKEN` | 该 zone 的最小必要 Custom Hostnames 权限；仅服务器持有 |
| `ANS_VISUAL_CNAME_TARGET` | 已配置的 SaaS CNAME 目标 |

用户添加域名后获得 `_ans-verify.<域名>` TXT 随机值及 CNAME。点击「检查归属与证书」先验证 TXT 归属，再申请 Custom Hostname；将服务返回的额外 DNS 记录展示给用户。TXT、CNAME、hostname 状态和 SSL 状态全部就绪才激活域名。申请前持久记录待核对状态，POST 结果不明确时只查询是否已创建，不重复申请。暂停只停止 ANS 提供网页，不删除外部 Custom Hostname。

官方配置参考：

- <https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/domain-support/hostname-validation/>
- <https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/worker-as-origin/>
