# ANS P3 社区团队与配额规范

> 状态：P3 团队协作已实现（2026-09-14；线上验收状态以独立核验为准，文档勾选不代表线上已验）
> 关联代码：`src/lib/team-service.ts`、`src/app/api/teams/**`、`src/app/api/admin/teams/**`、`src/app/teams/**`
> 数据模型：`Team`、`TeamMember`、`Competition`、`TeamCompetition`、`QuotaPool`、`QuotaLedger`（P3 之前已建表）

## 1. 目标

让用户能组队参加 AI / AIGC / 黑客松比赛，由平台发放比赛算力包，队长在队内二次分配，成员运行模板时消耗本人额度，全过程可审计、可对账。

## 2. 角色与权限矩阵

权限的**唯一真相来源**是 `teamPermissions(role)`（`src/lib/team-service.ts`）。页面只负责按能力隐藏入口，服务端每个写操作都重新校验，绝不信任客户端传来的角色。

| 能力 | OWNER 队长 | ADMIN 管理员 | MEMBER 成员 | 非成员 |
|---|---|---|---|---|
| `canInvite` 邀请成员 | ✅ | ✅ | ❌ | ❌ |
| `canRemoveMember` 移除成员 | ✅ | ✅（仅普通成员） | ❌ | ❌ |
| `canManageRoles` 调整角色 / 转让队长 | ✅ | ❌ | ❌ | ❌ |
| `canAllocateQuota` 分配队内额度 | ✅ | ✅（仅普通成员） | ❌ | ❌ |
| `canDeleteTeam` 解散团队 | ✅ | ❌ | ❌ | ❌ |
| `canViewQuota` 查看额度与运行记录 | ✅ | ✅ | ✅ | ❌ |

额外硬性规则：

- 不能邀请自己（`self_invite`）。
- 不能给自己分配额度（`self_allocation`），避免队长/管理员自肥。
- 管理员不能邀请管理员、不能移除或调整管理员（需队长操作）。
- 队长不能被降级、不能被移除（`last_owner`）。
- 队长退出前必须先转让队长（`owner_must_transfer`）。
- 同一团队同一时刻只有一位 OWNER；转让时原队长自动降为 ADMIN，`Team.ownerId` 同步更新。

## 3. 团队生命周期

```
创建团队（创建者=OWNER, ACTIVE）
   │
   ├─ 邀请（写入 TeamMember, status=PENDING）
   │      ├─ 对方接受 → ACTIVE（TEAM_MEMBER_JOINED）
   │      └─ 对方拒绝 → LEFT（TEAM_MEMBER_DECLINED）
   │
   ├─ 角色调整（TEAM_ROLE_CHANGED）/ 转让队长（TEAM_OWNERSHIP_TRANSFERRED）
   ├─ 移除成员（TEAM_MEMBER_REMOVED）/ 主动退出（TEAM_MEMBER_LEFT）
   └─ 解散团队（TEAM_DELETED，需回填完整团队名确认）
```

成员状态枚举 `MemberStatus`：`PENDING` 待接受、`ACTIVE` 在队、`LEFT` 已离开（拒绝/移除/退出统一落到 LEFT，保留历史便于重新邀请）。

## 4. 配额链路

```
管理员发放（refType="team"）
   └─▶ 团队额度池 granted
           └─▶ 队长/管理员分配（refType="team_member"）
                   └─▶ 成员 quotaAllowance（个人上限）
                           └─▶ 运行消耗 quotaUsed（P2 Run 结算）
```

- **两本账不混算**：管理员发放记 `refType="team"`，队内分配记 `refType="team_member"`；`getTeamQuota` 返回 `{ granted, allocated, available, used }`。
- 分配额度不能低于该成员**已消耗**的点数（`below_used`），也不能超过团队 `available`（`insufficient_team_quota`）。
- 额度变动同时写 `QuotaLedger`（含 `balanceAfter`）与 `AuditLog`，与状态变更同事务。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/teams` | 登录 | 我的团队 + 待处理邀请（仅本人） |

| GET | `/api/teams/[slug]` | 公开 | 团队详情；名单/额度/运行记录仅成员可见 |
| DELETE | `/api/teams/[slug]` | 队长 | 解散团队（需回填完整团队名） |

| PUT | `/api/teams/[slug]/members/[memberId]` | 队长/管理员 | 分配队内额度 |
| DELETE | `/api/teams/[slug]/members/[memberId]` | 队长/管理员 | 移除成员 |

## 7. 安全与一致性

- **同源校验**：所有写操作检查 `Sec-Fetch-Site` 与 `Origin`，跨站直接 403（`isCrossSite`）。
- **不泄露内部错误**：`teamFailure` 只回错误码与中文提示，未知异常统一 500 + `server_error`，原始错误仅落服务端日志。
- **禁止缓存**：所有团队接口响应带 `Cache-Control: private, no-store`。
- **并发防护**：额度分配、角色变更、接受/拒绝邀请统一走条件 `updateMany`（匹配当前 `status`/`role`/`quotaAllowance`），`count !== 1` 返回 409 `*_stale`，避免并发覆盖或超额发放。
- **可见性**：访客与非成员只能看到团队名称、简介、队长与成员数；名单、额度、运行记录仅成员可见。
