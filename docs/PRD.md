## 1. 产品目标

下一阶段把现有“发现 → 运行 → 收藏 → 复用”推进成：

```text
选择项目目标
  → 填写事实
  → 运行官方工作流
  → 检查并确认输出
  → 保存为项目成果
  → 复用到下一条工作流
```

用户在 10 分钟内必须看到第一份可编辑结果；完整项目包由多次运行逐步完成，不承诺一次点击生成全部材料。

## 2. 用户与权限

| 角色 | 需求 | 权限 |
| --- | --- | --- |
| 学生 | 完成私密项目材料 | 管理自己的项目、运行和成果 |
| 团队成员 | 在授权范围内协作 | 只访问所属团队设为可见的项目 |
| 创作者 | 提交模板或工作流 | 不获得他人项目的访问权 |
| 审核者 | 判断公开内容 | 不能审核自己的内容，不能浏览无关私密成果 |
| 管理员 | 成员、额度、审计 | 所有敏感操作留审计记录 |

公开身份继续使用昵称。学校、专业、年级和经历不作为注册必填项；需要时由具体工作流最小收集，并默认只存在私密项目中。

## 3. 范围

### 3.1 本期做

- 一个项目目标入口：求职项目、比赛项目、作品展示。
- 项目事实卡：问题、用户贡献、技术或方法、结果、证据链接、未知项。
- 8 条官方工作流的表单式入口；V0.2 先使用基于事实的官方草稿生成器。
- 每次运行生成一份成果草稿。
- 用户逐条确认事实；未确认内容保留“待确认”标记。
- 私密保存、版本记录、复制和导出。
- 项目内复用已确认事实，避免重复填写。
- 公开前的敏感信息检查和审核入口。
- 运行失败、额度不足、取消和退费的可理解状态。

V0.2 的通过范围只包含私密项目、事实确认、三份核心成果、版本和导出。真实 DAG、额度、退费、敏感信息阻断和公开审核仍是后续能力，不能算作本轮已完成。

### 3.2 本期不做

- 开放式聊天机器人或模型广场。
- 用户自由生成任意 Agent。
- 可视化节点编辑器重做。
- 自动向 GitHub 写入内容。
- 比赛报名、课程、支付、分成、直播和礼物。
- 公开简历市场。
- 对成果的公开社交推荐流。

现有 Prompt、模板、工作流、团队和额度能力保持可用，但不为了本期入口重构全部信息架构。

## 4. 关键体验

### 4.1 首次路径

1. 登录用户进入“项目包”。
2. 选择一个目标，并创建一个项目。
3. 填写最少 5 个事实字段；允许明确填写“暂无”。
4. 系统推荐一条最短工作流，同时显示预计时间和额度。
5. 用户确认后运行。
6. 页面持续显示排队、运行、成功、失败或取消。
7. 成功后逐段展示输出、事实依据和待确认项。
8. 用户编辑并保存；系统创建不可变版本。

未登录用户只看到两个匿名示例和一个登录入口，不展示他人真实内容。

### 4.2 双层详情

同一工作流详情包含：

- 学生视图：用途、输入、示例、时间、额度、运行按钮。
- 专业视图：已发布 DAG 版本、节点类型、输入输出和限制。

专业视图是只读解释，不在本期提供不受约束的节点编辑。

### 4.3 状态

```text
草稿 → 待确认 → 已确认 → 已归档
待确认 → 公开审核中 → 已公开 / 审核退回
```

运行状态沿用现有排队、运行中、成功、失败、取消，不向前端暴露供应商原始错误。

## 5. 功能需求

| 编号 | 需求 | 优先级 | 验收 |
| --- | --- | --- | --- |
| PRD-01 | 创建、重命名、归档自己的项目 | P0 | 非所有者不能读取或修改 |
| PRD-02 | 保存项目事实及证据链接 | P0 | “暂无”与空白有明确区分 |
| PRD-03 | 从项目运行官方工作流 | P0 | 运行绑定项目、用户、版本和输入快照 |
| PRD-04 | 展示额度预估、余额和失败退费 | P0 | 预估失败时不允许盲目执行 |
| PRD-05 | 保存成果版本并保留历史 | P0 | 旧版本不可被后续编辑覆盖 |
| PRD-06 | 标记事实确认状态 | P0 | 未确认内容不能进入公开审核 |
| PRD-07 | 导出 Markdown 项目包 | P0 | 导出只含用户有权访问的已保存版本 |
| PRD-08 | 将已确认事实复用到另一工作流 | P0 | 用户可在提交前移除任何预填字段 |
| PRD-09 | 检测手机号、证件号、邮箱、密钥和私有链接 | P0 | 高风险内容不能直接公开 |
| PRD-10 | 团队项目最小共享 | P1 | 每个成员的访问变更有审计 |
| PRD-11 | 公开作品页 | P1 | 默认私密，公开必须二次确认并审核 |
| PRD-12 | 基于目标和历史的推荐排序 | P2 | 推荐不可覆盖用户的明确选择 |

## 6. 内容与事实规则

- 模型只能整理用户输入和用户明确授权的材料。
- 缺失数据保持“待确认”，禁止补造数量、排名、收益、用户规模或性能。
- “我负责”和“团队完成”必须分开；无法区分时降级为“项目包含”。
- 引用他人仓库时，默认描述仓库事实，不把它改写成当前用户经历。
- 每次生成同时返回依据、不确定项和可能被追问的问题。
- 官方工作流输出使用固定结构，解析失败时成果保持失败，不保存半截伪成功内容。

## 7. 公开与安全

默认可见性是私密。可选范围只有私密、指定团队可见、公开三类。

公开必须依次满足：

1. 所有事实声明已确认。
2. 敏感信息检查通过，或用户移除风险内容。
3. 作者、来源、AI 辅助声明和许可证完整。
4. 按现有审核策略完成 AI 初审和人工复核。
5. 用户看到最终公开版本并再次确认。

私密成果不进入广场、搜索、推荐、日志正文或错误上报附件。

## 8. 指标

| 指标 | 事件 | 目标 |
| --- | --- | --- |
| 首结果时间 | 项目创建到首次成功保存 | 中位数 ≤ 10 分钟 |
| 项目包完成率 | 7 日内完成至少 3 条官方工作流 | ≥ 40% |
| 运行成功率 | 官方工作流成功 / 有效提交 | ≥ 90% |
| 事实确认率 | 已确认成果 / 已保存成果 | ≥ 80% |
| 复用率 | 14 日内使用同一项目再次运行 | ≥ 30% |
| 退费正确率 | 应退费且仅退一次 | 100% |

埋点不得包含项目正文、证据链接、邮箱或模型密钥。

## 9. 发布验收

V0.2 先按 [十人验证方案](./V0.2-十人验证.md) 验收。以下条款是 V0.3 接入真实工作流和公开能力后的发布验收：

- 新用户可在测试环境完成首条官方工作流并保存结果。
- 权限、审核、额度、退费和版本测试通过。
- 私密项目不能通过 API、搜索、日志或导出链接越权访问。
- 手机号、邮箱、密钥样本被公开流程阻断。
- 模型超时、额度不足、取消和重复提交都有稳定结果。
- `npm run verify` 通过，并完成数据库迁移演练。
- 回滚后旧 Prompt、模板、工作流和团队功能仍可用。

## 10. 开放问题

以下事项不阻塞私密项目包，但阻塞公开团队版：

- 团队成员离开后，历史成果保留还是撤回访问。
- 多位作者确认同一事实时，以谁的确认作为最终版本。
- 公开内容使用哪种许可证作为默认选项。

未决问题一律按“最小披露、禁止公开、保留审计”处理。
