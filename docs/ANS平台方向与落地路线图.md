# ANS 权威产品与架构总纲

> 状态：2026-10-05 用户确认的固定基线。本文是产品定位、首期范围和架构取舍的唯一权威入口。
> 用户确认：“就这个……确定一下权威架构，这次不变了，最快时间做出来。”
> 固定的是产品主线与边界，不是禁止修复问题；扩大范围或推翻架构必须由用户明确确认。

## 1. 唯一定位

ANS 是面向 AI 小白的成果型学习平台：用户带着一个真实目标，在引导下学会一个 AI 方法，使用工具完成成果，并保存、修改和复用。

学习内容负责教方法；提示词、模板和工作流负责操作；项目和成果版本负责保存结果。不是三个平行产品，也不是以功能数量、社区热闹或模型数量衡量成功。

首期以有真实课程、实习或个人项目的学生作为验证样本，但“校园社区”不再是平台总定位。现有注册限制本轮不改；扩大招生或开放注册需独立确认。

## 2. 首期固定范围

唯一核心路径：**看方法示例 → 新建私密项目 → 填写和确认事实 → 生成一份草稿 → 核对并在线修改 → 保存新版本 → 下载或再次使用。**

- 三份核心成果：简历项目条目、README 草稿、一页项目介绍。
- 五项事实：问题、个人贡献、方法、结果、证据；缺失和待确认必须明确。
- 主导航：开始学习、动手实践、我的成果。分别进入首页第一课、新建项目、项目列表。
- 学习内容首期为一节方法课和明确标注的教学示例，不冒充完整课程体系或真实用户案例，不把示例写进用户事实。
- 每次生成前展示额度成本；三份可逐份生成。现有批量接口保留，但不作为默认入口。
- 人工修改免费保存为新版本；导出只包含最新已保存版本。保留旧版本、来源与运行关联。
- 项目事实只供所有者访问；关联团队不授予读写私密事实的权限。
- 生成内容是草稿。确认输入不等于确认输出，提示词约束不等于杜绝幻觉。用户使用前检查贡献、数字、技术与证据。

产品验收不以“生成三份”冒充“完成学习”；生成数量只是进度提示，成果可用性要由真实用户检验。

## 3. 既有资产如何处理

| 资产 | 固定处理 |
| --- | --- |
| 身份、项目事实、工作流执行、额度、日志、成果版本、下载 | 复用并补齐首期路径，不重写 |
| 提示词、模板、通用工作流及另外五个项目工具 | 保留，移至资料入口或折叠区，不抢主入口 |
| 社区、团队、比赛、作品公开、等级、奖励等 | 不删除已有数据/路由，不继续扩张；与首期脱钩 |
| 已有作品公开与撤回 | 保留兼容：仅所有者明确申请特定版本，管理员审核；默认折叠，不自动公开。原作者/原申请人的撤回权保留 |
| MCP、Agent、原生多端、新支付/课程售卖/算力售卖 | 不纳入本期，不接新供应商，不新建通用引擎 |

“类似知识付费平台”指学习加工具加成果的体验，不表示现在已确定收费方案。既不承诺永久公益，也不默认启用支付；价格、课程权益、退款和单位成本验证另行决定。

## 4. 固定技术架构

继续使用 **Next.js / React / TypeScript + PostgreSQL / Prisma 的模块化单体**，响应式 Web 是本期唯一客户端。不增加依赖，不改数据库结构，不更换认证，不拆微服务。

```text
页面与交互：学习示例 / 项目列表 / 事实与成果工作台
    ↓ 输入契约与应用服务
contracts/projects → server/projects
    ├─ domain/projects：事实规范、输出规则、官方工作流定义
    ├─ server/workflows：不可变定义版本 → 运行快照 → 模型执行
    │    └─ 现有额度、幂等、超时、失败处理、审计
    └─ Prisma：Project → ProjectFact → Artifact → ArtifactVersion
         └─ 人工修改追加版本；导出读取已保存版本
```

- 页面/客户端不触达数据库、模型凭证或供应商；Route Handler 做鉴权、解析、调用服务、响应。
- 服务端逐对象检查 owner 权限；生成、列表、读取、修改和导出不能只依赖界面隐藏。
- 生成版本绑定运行与事实快照。人工修改版本保留来源版本、原事实快照哈希和来源运行信息，不伪装成模型执行结果，也不自动确认为事实。
- 人工保存使用预期版本号作并发检查，冲突不覆盖新内容；失败保留编辑框。
- `architecture.md` 描述工程细节，但不能扩张本文的首期范围。

## 5. 权威顺序与防止再次跑偏

1. 用户最新明确决定及安全/授权约束。
2. **本文**：定位、范围、架构固定基线。
3. `architecture.md`、`CONSTRAINTS.md`：与本文一致的工程约束。
4. 实际代码、测试、发布记录：证明“实现/验证/上线”状态，不反过来替代产品定位。
5. 旧 MRD/PRD/BRD、product-spec、implementation-plan、V0.2 文档、ANS-README：历史依据和可复用细节；冲突部分不再驱动开发。

以后新增功能先回答：它能否帮助首期用户完成上述路径？不能则进入候选，不自动进入开发。变更目标用户、核心路径、一级入口、支付、Agent、权限模型、数据库或技术栈，必须说明证据、代价及范围，并获得用户确认。小修复、可用性优化和安全修补不算改变方向。

## 6. 实施现状与最快交付顺序

2026-10-05 源码核查：真实模型工作流、额度扣退、幂等运行、成果版本和 Markdown 下载已经存在。旧文档“十人验证后才接模型”“导出只有文本”等描述已过时，不能据此重做一套。

本次本地实施顺序：

1. 固定权威入口，降级相互冲突的旧定位。
2. 收拢首页/导航/三份核心成果，增加方法示例、成本和草稿核对提示。
3. 补在线修改、追加版本、版本冲突处理；修复私密项目列表与公开管理的团队越权边界、事实来源保存和问号文案。
4. 自动化检查后审查改动；部署必须另获授权，不把本地完成写成线上完成。
5. 用 10 位真实目标用户验证，再按放弃点优化，不先开新模块。

首期交付门：相关组件/API/服务测试、类型检查、文档链接和边界检查通过；新增权限边界有拒绝路径测试。发布前还需测试环境数据库集成、真实生成的成本与结果验证、桌面/手机完整路径、既有发布门禁与回滚核查。模拟测试不替代这些证据。

本次证据：本地已实现上述首期改动，101 个测试文件 / 1478 个用例、生产与测试类型检查、文档及分层检查通过；生产构建真实通过（`.next/BUILD_ID` = `DgRHWRFLleqx8PDjnhISg`）。独立本地测试库上的端到端 33/33 与四项发布门禁（冒烟 26/26、11 页 axe 零违规、性能预算达标、生产依赖 0 漏洞）均已完成。模型网关已按权威探测修正：生产文本网关（McGrox）只接受不带前缀的模型名，白名单由 16 个收敛为网关实测可用的 3 个（`gpt-5.6-terra` / `gpt-5.6-sol` / `gpt-6-astra`），其余 13 个 TR 国模与带前缀旧 ID 一律 404 已移除；用户已于 2026-10-05 确认 McGrox 可作文本渠道。生产环境仍需真实 `RUN_BASE_URL` / `RUN_API_KEY` 才能验收。生产部署、回滚、备份恢复演练、真实生成质量与成本、十人验证仍未完成，本地测试环境不等于上线。详见 [本轮验收记录](./acceptance.md)，不得用历史“全门禁通过”替代。

10 人验证保留既有目标：至少 6 人在 20 分钟内完成三份自己愿意使用的成果，与 ChatGPT 加文档比较，记录实际完成时间、修改量、虚构事实、放弃点和再次使用意愿。出现越权必须修复；不能把“目标零虚构”说成系统保证。**目前没有本轮十人验证结果。**
