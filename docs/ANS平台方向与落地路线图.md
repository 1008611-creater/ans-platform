# ANS 平台方向与落地路线图

## 1. 目标与决策

ANS 的长期方向是面向学生群体的 AI 原生社区与成果生产平台，以“AI never stops”为品牌表达。它帮助学生围绕求职简历制作、AI 相关赛事参赛、作品产出和能力提升，完成从发现方法、使用工作流到沉淀成果、获得反馈的循环。

方向图是长期产品输入，不是要求当前版本同时建设全部功能的开发命令。当前最近门槛仍是 V0.2 私密学生项目包的十人对照验证。先证明项目事实输入能带来可信成果，再逐步扩大到通用工作流、团队赛事和公开作品社区。

产品层级建议：

1. **近期验证层**：私密项目空间、事实记录、生成草稿、人工确认、版本化成果及授权边界。
2. **平台能力层**：新手引导、社区提示词、预制工作流、运行可靠性、团队协作、作品发布和治理。
3. **生态增长层**：MCP/CLI/Agent 接入、多端体验、创作者激励及经验证的商业化尝试。

| --- | --- | --- | --- |
| 学生群体与成果导向 | 简历、赛事、作品与能力提升等场景入口 | 场景目录、项目空间、成果类型和指标 | 纳入定位；先由项目包验证一个窄场景 |
| 新手引导 | 目标选择、分步引导、空状态、示例项目 | onboarding 状态与场景配置；复用现有身份和项目域 | V0.2 后按验证反馈建设 |
| 社区提示词管理 | 用户提交、分类、搜索、可视化浏览 | content 域的提交/审核/版本/检索；AI 分类仅作建议 | 现有 Prompt/模板资产先复用，避免平行内容库 |

| 作品广场 | 公开浏览、作品页、点赞评论收藏、个人展示 | Artifact 发布快照、可见性/撤回、moderation、互动域 | V0.2 默认私密；先完成授权和隐私模型 |
| 创作者激励 | 贡献记录、曝光、奖励与申诉 | 可审计的贡献账本和规则版本 | 作品供给和治理稳定后再试点 |
| 多端 | 手机、电脑与未来客户端体验 | 响应式 Web 为单一事实源；API/契约可复用，客户端逐步增加 | 先保证 Web 核心任务移动端可用；不为多端过早拆服务 |

| 外部生态 | MCP、CLI、Codex/其他 Agent 联动 | 版本化 API、OAuth/密钥、限流、作用域授权和审计 | 内部契约稳定后以最小只读/受限写入接口试验 |

## 3. 目标架构演进

保持当前 Next.js + PostgreSQL + Prisma 的模块化单体。先把领域边界、数据授权和运行可靠性做好，只有在负载、团队所有权或部署隔离有证据时才拆分服务。

```text
体验层：Web / 移动 Web / 后续客户端
  └─ 应用入口：Next.js 页面、Route Handler、服务端动作
       └─ contracts：输入输出 schema、API 与事件契约
            └─ domain：identity / content / projects / artifacts /
                       workflows / runs / teams / competitions /
                       community / governance / billing
                 └─ server ports：数据库、模型、文件、队列、执行器
                      └─ adapters：Prisma / provider / object storage / worker
```

关键架构决策：

- 以现有 `contracts / domain / server` 分层为硬边界；Route Handler 只负责鉴权、解析契约、调用用例和映射响应。
- 将工作流定义、发布版本、运行实例、节点运行、Artifact 版本分开。运行必须绑定不可变的工作流版本和输入快照，结果带来源与运行状态。
- 项目事实、用户声明、模型推断、外部来源和人工确认分别标记来源与可信状态；生成内容默认是草稿，不因模型输出自动成为事实或公开成果。
- 对象可见性以服务端授权为准，默认私密。列表、搜索、导出、下载、异步执行和外部 API 均执行同一授权策略；撤回公开后清理缓存/索引并保留审计记录。
- 执行器通过 `WorkflowExecutor` 一类的内部端口适配，任务队列、预算、超时、重试、幂等键、取消、日志脱敏和产物存储由平台掌握。第三方 Harness/Agent 只能在授权工具和资源作用域内工作。
- 不允许把任意代码执行、任意网络访问或用户密钥透传给 Agent 作为默认能力。需要隔离执行时先完成威胁建模、沙箱评估和 ADR。
- MCP/CLI/API 复用同一应用用例及契约，不直接访问数据库；凭证具备最小作用域、轮换/撤销、限流、配额和审计。
- 互动、创作者激励、付费权益按独立领域逐步加入，避免让社交指标或商业逻辑污染项目成果的事实与授权模型。

## 4. 分阶段落地与验收门

### 阶段 A：V0.2 私密项目包十人验证（当前）

**范围**：项目空间、事实记录、生成草稿、人工确认、Artifact 版本与私密授权边界。公开广场、排行榜、收费和任意 Agent 执行不在此阶段。

**完成条件**：
- 10 位目标学生完成任务；至少 6 位能在 20 分钟内完成三份核心成果，对照结果不差于 ChatGPT 加文档，虚构事实和越权均为 0；关键失败点有记录和修复结论。
- 对照记录与 AI 生成结果可区分；每项成果可追溯输入事实、工作流版本、运行和人工修改。
- 私密项目的未授权读取/变更/下载/公开均被服务端拒绝，越权用例为 0。
- 公开申请、审核等入口不仅从界面隐藏，相关服务端 API 也被关闭或受明确权限/功能开关保护。
- 数据库迁移、备份与恢复演练通过；实际浏览器流程、可访问性和性能检查有真实结果，不以“跳过”视作通过。

### 阶段 B：新手引导与内容供给

**范围**：目标选择、示例项目、清晰空状态；提示词/模板提交、审核、分类建议和搜索；预制工作流目录。

**进入条件**：阶段 A 找到可重复的核心任务与主要放弃点。
**验收**：新用户能在可用性测试中独立找到并完成首个核心工作流；内容分类、搜索和审核质量达到事先约定阈值；发布版本可回滚且来源明确。

### 阶段 C：可靠工作流与成果闭环

**范围**：运行队列、节点状态持久化、重试/取消/幂等、成本与额度、失败恢复、产物导出和反馈。

**进入条件**：至少一个工作流被真实重复使用，且失败样本足以确定可靠性目标。
**验收**：运行成功率、p95 延迟、失败恢复率、单次成本和用户可接受度达到发布前设定的 SLO；工作流版本变更不篡改历史运行。

### 阶段 D：30 人校内试点与团队赛事

**范围**：邀请制 30 人试点；在明确合作赛事、规则和运营负责人的前提下，增加团队成员、角色、任务阶段、提交与评审。

**进入条件**：阶段 C 的可靠性、支持能力、隐私流程和事故处理已验证。
**验收**：团队成员权限正确；个人/团队成果归属、授权和撤回可操作；赛事流程由真实组织方走通并能处理争议。

### 阶段 E：作品广场与创作者激励

**范围**：用户明确选择的公开作品快照、作品页、检索、互动、举报和审核；小规模创作者激励试点。

**进入条件**：公开授权文案、审核 SLA、版权/隐私投诉与撤回机制、反滥用方案均有负责人。
**验收**：公开仅针对授权版本；撤回能在约定时间内从展示/搜索/缓存中移除；互动和激励规则可审计、可申诉。

### 阶段 F：外部生态、多端与商业化实验

**范围**：受限 MCP/CLI/API 试点；补齐移动端核心任务；依据访谈和成本数据试验算力、课程或创作者权益等模式。

**进入条件**：核心 API 契约、权限、计量、支持和安全审查稳定；具体商业假设有客户与成本证据。
**验收**：每个集成明确作用域、配额和撤销路径；多端核心流程一致；商业试验有正向单位经济或明确停止结论。

## 5. 跨阶段质量门

每个阶段要同步交付：产品规格与指标、领域模型和迁移方案、权限/隐私威胁审查、中文及其他目标语言的界面文案、自动化测试、运维/回滚说明和用户支持预案。阶段发布必须提供真实证据：`npm run verify` 全通过，数据库迁移与恢复演练通过，目标浏览器冒烟及可访问性/性能检查未跳过，且没有未处理的高危越权或数据泄露问题。

关键指标按阶段观察：首个任务完成率、完成时长、生成可用率、人工修改量、重复使用率、运行失败及恢复率、单位成本、越权事件数、公开撤回完成时间、举报处理时长。先定义口径，再采集数据；不为追逐留存而默认公开学生数据。

## 6. 资源与待决策项

方向图提到校内团队数百人、核心成员十余人。这是需要负责人核实的组织输入，不作为已确认排期或承诺。每阶段启动前明确产品负责人、技术负责人、学生/赛事运营、隐私与内容治理责任人及可投入容量。

待 ADR/专项评估：
- Harness/Agent 候选的隔离能力、工具授权、可观测性、成本、可替换性与维护成本；在评估完成前仅建设平台执行器端口。
- 队列与 Worker 的实现选择及部署拓扑；以阶段 C 的实际并发和可靠性需求决策。
- 公开作品授权、学生个人信息处理、内容治理和成果知识产权边界。
- 商业模式、支付与权益模型；有明确需求和单位经济后再定。

## 7. 暂缓项

在相应阶段门通过前，不进入当前迭代：全量公开作品广场、开放式 Agent/任意代码执行、完整团队赛事系统、重型多端原生客户端、直播/娱乐流量模块、付费课程/算力售卖、第三方账号代购或代付。它们保留在方向储备中，避免提前形成安全、运营和维护负担。
