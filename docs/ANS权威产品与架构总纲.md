## 当前修订：以项目发现与成熟工作流为中心

**定位**：ANS 面向愿意拥抱 AI、持续学习与创造的人，精选值得做的项目，把方法和可执行流程交到小白手里，帮助用户完成自己的作品。首批来自本校、CAUHub、群和公众号。

**主路径**：发现项目 → 看成果与价值 → 了解模型、提示词、Skill 和方法 → 输入自己的内容 → 确认关键决策 → 运行预置工作流 → 核对、修改、保存成果 → 用户选择分享或交易。

### 产品对象与入口

| 对象 | 内容 | 关系与边界 |
| --- | --- | --- |
| 公开项目卡 | 示例效果、用途、来源、作者、方法、输入要求、价格与就绪状态 | 可以是方法、开源项目、知识、服务、问题解决方案；不等于用户私密项目 |

| 用户私密项目 | 用户输入、事实、任务、生成记录、成果和版本 | 不随项目卡浏览或生成自动公开；延用现有鉴权和所有权 |
| 服务交易 | 购买内容、服务范围、订单、交付、争议、结算 | 与生成算力点分开；状态和支付来源须可追踪 |

分类采用「大类 → 小类」，来源单独标注，支持组合筛选与搜索：学习成长、求职与作品、AIGC 创作、网站与开发、GitHub 宝藏、掘金与商业、效率与生活、比赛与团队。项目可以保持稳定的主分类；扩充时再增加辅助标签，避免重复卡片。

> **ANS 是一个把用户的目标变成可验收成果的 AI 平台。**

- **首期场景（阶段一）**：**成果型学习**——面向 AI 小白，用户带着一个真实目标来，
  在引导下学会一个 AI 方法，使用工具完成成果，并保存、修改和复用。
- **长期形态（阶段四）**：**AI 工作操作系统**——用户只需说明"我想完成什么"，
  系统把目标编译成可执行工作流，跑完、质检、交付，并把经验沉淀成下次更快的 SOP。

**两者共用同一个内核**：

```
目标 → 澄清/引导 → 计划/示例 → 执行/生成 → 质检 → 人工确认 → 保存版本 → 沉淀复用
```

**不是三个平行产品，也不以功能数量、社区热闹或模型数量衡量成功。**

**首期验证样本**：有真实课程、实习或个人项目的学生。
「校园社区」不是平台总定位；现有注册限制本轮不改，扩大招生或开放注册需独立确认。

# 2. 演进路线（四阶段）

| 阶段 | 名称 | 形态 | 启动条件 | 当前状态 |
|---|---|---|---|---|
| **一** | **成果型学习** | 人工引导 + 单次生成 + 版本管理 | — | **← 当前唯一在做的** |
| 二 | SOP 引擎 | 把可复用流程变成可执行图（DAG + 状态机 + 幂等） | **阶段一十人验证通过** | 未启动 |
| 三 | 吉祥物 Agent | 自然语言入口，Agent 自动规划与执行 | **阶段二稳定运行** | 未启动 |
| 四 | 工作操作系统 | 多场景扩展（视频、设计、代码…） | **阶段三真实验证** | 未启动 |

## 2.1 阶段门禁（硬规则）

**未满足启动条件的阶段，视为「不得开工」。**

- 团队**不得**因为"顺手"或"设计得更优雅"而提前实现后续阶段的能力
- 任何跨越阶段的工作，必须**先由用户确认并修改本节**
- 阶段一的验收未通过前，**不得**把阶段二~四的任何功能计入交付

## 2.2 为什么是这个顺序

1. **阶段一有真实用户样本**（学生 + 真实项目），能最快拿到反馈
2. **阶段一的流程本身就是 SOP 的雏形**（看示例 → 建项目 → 填事实 → 生成 → 改 → 存）
   —— 做扎实了，阶段二才有可抽象的素材
3. **阶段二没有可执行流程做素材时，SOP 引擎就是空壳**
4. **阶段三的 Agent 需要阶段二的执行器才能干活**，否则只能聊天（这正是愿景文档禁止的）
5. **阶段四需要前三个阶段的真实数据**才知道该扩展什么场景

**一句话**：**能力是长出来的，不是设计出来的。**

# 3. 阶段一：固定范围（原基线，保留原文效力）

## 3.1 唯一核心路径

```
看方法示例 → 新建私密项目 → 填写和确认事实 → 生成一份草稿
→ 核对并在线修改 → 保存新版本 → 下载或再次使用
```

- **三份核心成果**：简历项目条目、README 草稿、一页项目介绍
- **五项事实**：问题、个人贡献、方法、结果、证据；缺失和待确认必须明确
- **主导航**：开始学习、动手实践、我的成果（分别进入首页第一课、新建项目、项目列表）
- 学习内容首期为一节方法课和明确标注的教学示例，**不冒充完整课程体系或真实用户案例**，
  不把示例写进用户事实
- 每次生成前**展示额度成本**；三份可逐份生成；现有批量接口保留，但不作为默认入口
- **人工修改免费保存为新版本**；导出只包含最新已保存版本；保留旧版本、来源与运行关联
- **项目事实只供所有者访问**；关联团队不授予读写私密事实的权限
- 生成内容是**草稿**。确认输入不等于确认输出，提示词约束不等于杜绝幻觉。
  用户使用前检查贡献、数字、技术与证据

**产品验收不以"生成三份"冒充"完成学习"**；生成数量只是进度提示，成果可用性要由真实用户检验。

## 3.2 既有资产如何处理

| 资产 | 固定处理 |
|---|---|
| 身份、项目事实、工作流执行、额度、日志、成果版本、下载 | **复用并补齐**首期路径，不重写 |
| 提示词、模板、通用工作流及另外五个项目工具 | 保留，**移至资料入口或折叠区**，不抢主入口 |
| 社区、团队、比赛、作品公开、等级、奖励等 | **不删除已有数据/路由，不继续扩张**；与首期脱钩 |
| 已有作品公开与撤回 | 保留兼容：仅所有者明确申请特定版本，管理员审核；默认折叠，不自动公开。原作者/原申请人的撤回权保留 |
| MCP、Agent、原生多端、新支付/课程售卖/算力售卖 | **不纳入阶段一**，不接新供应商，不新建通用引擎 |

「类似知识付费平台」指学习加工具加成果的体验，**不表示现在已确定收费方案**。
既不承诺永久公益，也不默认启用支付；价格、课程权益、退款和单位成本验证另行决定。

## 3.3 新增功能的判断规则

以后新增功能**先回答**：它能否帮助首期用户完成上述路径？

- 不能 → 进入候选，**不自动进入开发**
- 变更目标用户、核心路径、一级入口、支付、**Agent**、权限模型、数据库或技术栈
  → 必须说明**证据、代价及范围**，并获得用户确认
- 小修复、可用性优化和安全修补 → **不算改变方向**

# 4. 固定技术架构

继续使用 **Next.js / React / TypeScript + PostgreSQL / Prisma 的模块化单体**，
响应式 Web 是本期唯一客户端。

**不增加依赖，不改数据库结构，不更换认证，不拆微服务。**

## 4.1 技术栈

| 项 | 值 |
|---|---|
| 框架 | Next.js 16.0.7（App Router）+ React 19.2 |
| 语言 | TypeScript 5 |
| 数据库 | PostgreSQL + Prisma ORM 6.19 |
| 认证 | NextAuth.js 5 (beta)：credentials / GitHub / Google / Azure |
| 样式 | Tailwind CSS 4 + Radix UI + shadcn/ui |
| i18n | next-intl，11 种语言 |

## 4.2 分层

```
页面与交互：学习示例 / 项目列表 / 事实与成果工作台
    ↓ 输入契约与应用服务
contracts/projects → server/projects
    ├─ domain/projects：事实规范、输出规则、官方工作流定义
    ├─ server/workflows：不可变定义版本 → 运行快照 → 模型执行
    │    └─ 现有额度、幂等、超时、失败处理、审计
    └─ Prisma：Project → ProjectFact → Artifact → ArtifactVersion
         └─ 人工修改追加版本；导出读取已保存版本
```

- 页面/客户端**不触达**数据库、模型凭证或供应商
- Route Handler 做鉴权、解析、调用服务、响应
- **服务端逐对象检查 owner 权限**，生成、列表、读取、修改和导出不能只依赖界面隐藏
- 生成版本**绑定运行与事实快照**
- 人工修改版本保留来源版本、原事实快照哈希和来源运行信息，
  **不伪装成模型执行结果**，也不自动确认为事实
- 人工保存使用**预期版本号做并发检查**，冲突不覆盖新内容；失败保留编辑框
- `architecture.md` 描述工程细节，但**不能扩张本文的首期范围**

# 7. 阶段二~四：长期方向（**未授权，不得开工**）

> ⚠️ **本节是方向说明，不是任务。**
> 启动条件见第 2 节：**阶段一十人验证通过之前，本节任何内容不得进入开发。**
> 本节存在的作用是：让团队理解"为什么现在做阶段一"，避免因为看不到全局而怀疑方向。

## 7.1 阶段二：SOP 引擎

把可复用流程变成**可执行图**（不是说明书）。

**节点必备字段**：
```
node_id / node_type / label / inputs / outputs / preconditions / executor
permission_scope / idempotency_key / timeout / retry_policy
concurrency_group / estimated_cost / artifact_paths / quality_gate
human_approval_required / on_error
```

**节点类型**：目标输入、信息收集、文件输入、资产选择、提示词编译、模型调用、
脚本执行、并发组、等待、质量审查、人工确认、条件分支、失败重试、人工接管、
文件导出、通知、沉淀 SOP

**运行状态机**：
```
DRAFT → PLANNED → WAITING_APPROVAL → QUEUED → RUNNING → PAUSED
→ SUCCEEDED / FAILED / CANCELLED / NEEDS_HUMAN → ARCHIVED
```

状态转换必须有：操作者、时间、原因、输入版本、输出版本和事件记录。

**并发**：默认最大 3，**后端强制限制**，不依赖前端；超限进队列；
单节点失败不影响已完成节点；支持单节点重跑。

## 7.2 阶段三：吉祥物 Agent

**产品定义**：以吉祥物 Agent 为入口，把自然语言目标编译成可执行工作流。

**六种身份**：入口 / 导航员 / 规划器 / 执行器 / 质检员 / 教练

**它不是客服。** 每次回复必须至少完成一项：
减少一个关键不确定性 / 收集一个必需输入 / 生成一个可执行节点 /
启动或暂停或恢复或重试或取消一个真实任务 / 展示真实进度或产物 /
指出一个可验证的风险 / 沉淀一个可复用资产。

**禁止**用"好的、收到、非常棒、我会继续"等空回复替代行动。

**角色状态**：待机 / 监听 / 思考 / 工作 / 需要输入 / 需要确认 / 成功 / 失败 / 被打断。
状态转换必须由**真实事件驱动**，不得只靠随机动画。

**输出协议**（机器可解析 + 用户可读两层）：
```json
{
  "message": "给用户看的短消息",
  "intent": "inspect|plan|confirm|run|pause|resume|cancel|retry|rerun_node|review|export|save_sop",
  "needs_user_input": [],
  "plan": null,
  "tool_calls": [],
  "risk_flags": [],
  "next_action": "用户下一步可以做什么",
  "evidence": []
}
```

**实时语音与口型**（阶段三的后半）：
- 必须支持：按住说话、自动语音活动检测、实时字幕、流式 TTS、
  用户打断 Agent、被打断后停止音频与口型、继续未完成任务、重播上一句、
  关闭语音回退文字、断网重连、音频队列去重
- 口型优先用供应商的音素/Viseme 时间轴；没有时用**可控近似映射**，
  **不得随机张嘴**
- 所有延迟必须**真实测量记录**，不能只写目标值

## 7.3 阶段四：工作操作系统

把阶段三的引擎扩展到多场景（视频、设计、代码…），
并形成"生产复利"：每次任务沉淀为模板、节点、提示词、资产、质量规则、
失败经验、成本曲线、团队知识卡。

**这一步的前提是阶段三已有真实用户与真实数据。**

## 7.4 阶段二~四的共同红线

即使将来启动，也必须遵守：

- **不创建第二套系统**：不新建第二套登录/管理员/项目/权限/Logo 体系
- **不绕过鉴权**调用受限工具
- **密钥不出现在**前端、Git、截图、日志或模型上下文
- **每次"已完成"必须有证据**：代码位置、接口响应、页面行为、任务记录或测试结果
- **不以界面完成、接口存在或文档写完作为完成标准**，必须验证一次真实端到端任务
- **任何失败必须可定位、可恢复、可重试或可人工接管**
- **不得在阶段 N 未通过验收前，把主要时间投入到阶段 N+1 的装饰性工作**
