## Pattern 1: Real desk realism beats abstract service cards

What works:

- lamp light
- laptop edge
- paper table
- red pen marks
- phone question bubble
- sticky notes

Why it works:

- feels like a parent is actually dealing with the problem
- creates trust faster than abstract diagrams
- looks like a native Xiaohongshu save post, not a consulting brochure

## Pattern 2: One mistake plus one action

Good visible lines:

- `别只看学校名`
- `先查4栏`
- `不是先选学校，是先看能不能报`
- `不知道表格怎么列？评论：专业组`

Why it works:

- short
- human
- direct
- easy to read in 2 to 3 seconds

## Pattern 3: Save value must be concrete

Better save targets:

- 4 fields
- 1 checklist sheet
- 1 compare frame
- 1 empty template

Avoid vague save bait like:

- `一定要看全`
- `这张图很重要`
- `看完就懂`

## Pattern 4: Proof should look handled, not announced

Good proof forms:

- half-filled printed table
- sheet with handwritten marks
- phone screen showing a real question
- side-by-side wrong vs right action

Bad proof forms:

- abstract dashboard with no scene
- empty chart pretending to be professional
- long explanation saying the result is professional

## Pattern 5: Comment handoff should stay light

Better:

- one keyword
- one low-pressure next step

Example:

- `评论：专业组`

Worse:

- multiple actions at once
- hard sales CTA
- public wall of disclaimers

## Pattern 6: Public cards do not need the full boundary lecture

Public note priority:

1. click
2. save
3. comment

Boundary, privacy, and service scope belong later in:

- private reply
- comment follow-up
- pre-sale explanation

## Pattern 7: Production method matters

Useful Hermes direction:

- Image2 creates the photographic base mood and scene
- local overlay or HTML/CSS handles Chinese precision
- do not trust generated Chinese to carry the final message

This is often the difference between "AI made a picture" and "a creator made a post".

## Pattern 8: Zero-view recovery sequence

When a note has 0-10 early views, the next public note should look less like a service and more like a real creator's observation.

Recommended 5-card structure:

1. click: one audience marker plus one wrong action
2. conflict: why the wrong action creates trouble
3. checklist: 3-5 concrete fields worth saving
4. proof: a half-filled sheet, red pen mark, phone question, or handled document
5. comment: one keyword only

What works:

- `先别逼孩子定专业`
- `山东先看位次`
- `河南600分，别先问学校`
- `广东看专业组`
- `评论：清单`

What to avoid:

- immediately publishing another near-duplicate service post
- turning the final image into a disclaimer card
- using empty tables as proof
- adding multiple comment/private-message actions
