# MiniMax H3 创作使用

## 冠军入口

提交 RunningHub 前先应用 [`runninghub-workflow-api`](../runninghub-workflow-api/SKILL.md) 的统一上传、凭据、结算和回传规则；本 Skill 只生成 MiniMax H3 创作契约。

## 作用与边界

本技能负责把创作意图变为可执行的**创作契约**：输出规格、素材分工、通道建议、结构化提示词及不可违反的视觉/声音约束。

实际 API 选择、提交、轮询、下载和 RH 币结算一律交给 `minimaxh3skill`。不要在这里伪造 API 参数、工作流 ID 或已发布通道；不要自动切换到其他视频 Provider。

真实生成会产生费用。仅在用户明确授权本次提交后，才可调用 `minimaxh3skill`；结算优先 RH 币，完成后以 `consumeCoins > 0` 且 `consumeMoney` 为空或 `0` 作为合格证据。

## 路由

先将用户提供素材按职责分类，再根据当前已注册的 RunningHub 通道选择最小可行输入：

| 创作需求 | 优先通道 | 适用条件 |
| --- | --- | --- |
| 仅描述一个新画面 | `text` | 无参考素材 |
| 从一张图开始并用音频带动表演/节奏 | `image-audio` | 有 1 张图和 1 条音频 |
| 多个镜头或资产逐步承接 | `multi-image` | 最多 3 张连续关键帧 |
| 四个镜头/资产需明确分工 | `four-image` | 最多 4 张图，尤其适合品牌片和片尾卡 |
| 锁定首尾状态或变形结果 | `first-last` | 有首帧和尾帧；按通道契约允许的输入数提交 |
| 只锁定结束状态 | `last-frame` | 有尾帧 |

若需要的原生能力超出已注册通道（例如超过 4 张图、视频参考、多个音频或图/音/视频混合），转给 `runninghub-workflow-api` 定制工作流并获得**实际发布后的 API 契约**。官方模型能力说明不能直接当作当前 RunningHub 工作流已经暴露的输入字段。

当前已预先导入 5–9 张图 + 1 条音频的候选工作流，见 `minimaxh3skill/references/candidate-workflow-registry.json`。这些候选只用于缩短后续定制时间，仍需 API 页面、dry-run 和用户授权的真实 RH 币任务三层证据，未完成前不作为正式路由。

## 制作流程

### 1. 先写创作契约

向用户或任务输出下列内容；缺少素材时，只问影响路线的最少问题：

1. 输出：时长、画幅、交付目的、是否需要清晰文字/原生声音。
2. 素材职责：每张图、每段视频、每段音频各自唯一的作用。
3. 连续关系：从哪张图到哪张图、保留什么、发生什么转场。
4. 硬约束：必须保留和绝对禁止的元素、文字、镜头或声音。
5. 目标通道：说明为什么它覆盖当前素材，不夸大其能力。

不要让两份参考素材同时承担相互矛盾的角色。推荐职责：图 1 管整体场景/氛围/质感，图 2 管人物一致性，图 3 管产品或关键资产，图 4 管 Logo、片尾卡或文字视觉；音频管台词、表演节奏或音乐节拍。

### 2. 检查能力边界

官方 MiniMax H3 的创作边界详见 [creative-contracts.md](references/creative-contracts.md)。先按当前通道注册表/API 页面检查真实输入节点、文件数和格式，再把官方边界用作“是否值得定制 API”的判断依据。

常规计划使用 4–15 秒、24 FPS，并默认视频原生带声音。用户要求的画幅可从 `21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16` 中选择；当前通道若未公开画幅字段，则在提示词明确画幅，不能假设可传字段。

### 3. 生成结构化提示词

按顺序组织，不必把所有段落写成长文；优先用准确、可验证的描述。

1. **输出规格**：时长、画幅、分辨率意图、声音目标。
2. **参考职责**：逐一写明图/视频/音频分别控制什么。
3. **场景与叙事**：地点、人物、事件和情绪主线。
4. **镜头、剪辑、转场**：景别、运动、镜头断点、转场及其节奏。
5. **人物与产品动作**：谁在做什么，产品怎样自然融入动作。
6. **文字与版式**：精确文本、字体气质、出现位置/次数/节奏与清晰度。
7. **声音与节奏**：台词、环境声、BGM、关键音画同步点。
8. **风格与硬约束**：材质、光线、综合色彩，及明确禁止项。

每次要确保提示词中的素材数量、职责和选定通道一致。需要可读文字时，同时写“文本仅出现一次、清晰可读、不得乱码/错拼”；并避免旋转、弹跳或大幅飞入飞出等会损害可读性的动效。

## 专项创作规则

### 连续多图关键帧

- 逐图指定：保留物、变化物、镜头如何推进、如何到达下一图。
- 固定遮罩、产品、人物特征、Logo 或版式时，写位置、尺寸、边缘和出现次数均保持一致。
- 用明确转场词，例如硬切、扫视、运动模糊、光学拖影、曝光闪烁、遮罩揭示、分屏重组；同时说明禁止的转场。
- 超过当前通道图数时，先定制/发布可验证 API，不能将三图或四图通道当成九图通道。

### 品牌与产品片

- 产品必须被人物自然使用、穿着、展示或与动作产生关系；不只在画面里静置。
- 写清商业气质与节奏，例如高级、冷感、克制、灵动；必要时禁止“普通剧情片”或“普通电商广告”的走向。
- 片尾文字/Logo 单独给素材职责，并指定露出长度、位置和可读性。

### 影视预告

- 用短 Shot 分段建立信息递进，重点镜头可以用 `Hard cut` 明确断点。
- 标题要指定字体气质、字距、材质、发光/颗粒程度、出现和离场方式。
- 将音画同步写到关键秒点：低频建立、冲击/黑场、标题 hit、最终定格；禁止模仿现有受版权保护的旋律。

### MG、片头和文字动效

- 写构图元素的出现次序，指定色块、线框、画格、剪影和文本如何进入、遮罩、停留和离开。
- 需要强节奏时，写“所有转场跟随鼓点”，并列出硬切、色块切、分屏、画格贴入等具体方式。
- 当文本是关键信息，限制其次数、拼写和职位/名称的唯一性；不要只笼统地说“有动态文字”。

### 人物与音频参考

- 用 `image-audio` 时，图像负责人物/场景/产品一致性，音频负责表演、台词或节奏；提示词仍需给出音画同步点。
- 音频不可孤立理解为万能控制器。没有与当前通道匹配的图像或视频输入时，先调整素材计划或定制通道。

## 交接给执行技能

创作契约完成后，向 `minimaxh3skill` 提供：目标通道、素材清单（仅本次任务的临时引用）、最终提示词、时长/画幅要求以及用户已明确授权本次生成的事实。执行完成后由该技能核验任务结果和 RH 币结算；本技能不保存密钥、余额、素材、结果 URL 或临时签名 URL。
