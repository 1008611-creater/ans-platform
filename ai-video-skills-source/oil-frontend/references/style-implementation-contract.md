# 样式实现规则

> 当任务要按设计稿、设计规范或项目 Token 修改样式，或修复同类组件样式不一致、控件状态跳动、图标偏移时读取。视觉层级、配色、排版和设计方向这类设计判断不在本规则范围。

## 边界

本规则负责把已经确定的视觉结果正确、稳定地写进代码。“应该长什么样”，例如层级怎么排、用什么配色和字体、间距该多大、整体风格如何，以设计稿、项目设计规范或用户的明确要求为准；都没有时沿用相邻同类页面的做法，不自行发明新的视觉方案。

## 取值来源

按以下顺序确定取值：

1. 设计稿或用户明确给出的值；
2. 项目的设计变量、主题和组件变体；
3. 相邻同类组件与页面中已经符合规范的实现。

找不到对应角色时，只为当前需要的角色补最小的变量或组件变体，不顺手建立完整的设计系统。

没有渲染证据时，只修源码能够确定的硬问题，例如任意值绕过变量、同一状态使用不同样式、`transition: all`、实例覆盖组件内部；不声称视觉已经变好。

## 实现规则

- 组件使用语义变量，不借用“当前看起来一样”的其他角色的值；缺少角色时补角色，不拿边框色充当文字色。
- 相同关系使用同一个间距变量。页面负责区域排列和区域间距，组件负责自身内部 padding；父级 `gap` 和子级 `margin` 不重复制造同一段距离。
- 文字使用项目已有的文字角色，不按标签名临时指定字号；需要纵向比较的数字使用等宽数字。
- 只有溢出策略明确时才截断；参与识别的名称保留查看完整内容的入口，不靠更短的 `line-clamp` 掩盖问题。
- 悬停、按下、聚焦、禁用和处理中状态由共享组件维护；状态切换不改变控件的几何尺寸，预留图标和加载指示的位置。
- 图标继承 `currentColor`，同一资源不维护多份只有颜色不同的文件；图标偏心时修 SVG 的 `viewBox` 或共享图标容器，不在每个使用位置补偏移。
- 嵌套表面的圆角、边框和阴影沿用组件变量，不在实例上各自调整。

## 常见问题与代码落点

| 问题 | 优先修改 | 不要做 |
| --- | --- | --- |
| 同类组件看起来不一致 | 修共享变量、默认样式或含义稳定的变体 | 用逐个实例覆盖掩盖共享实现的不一致 |
| 内容太挤或太散 | 统一父布局 `gap` 和组件内部 padding | 同时叠加 margin、gap 和空占位 |
| 控件跳动 | 稳定尺寸，预留图标或加载位置 | 状态切换时改变 padding 或边框宽度 |
| 图标不齐 | 修图标资源或共享图标容器 | 为每个使用位置写不同的 `translate` |

## 验证

- 用本次受影响的真实内容与状态检查溢出和一致性，至少看改动组件的默认状态和本次涉及的交互状态。
- 修改共享变量、组件或变体后，按使用位置确认其他语义状态仍能区分。
- 没有渲染检查时明确写“未验证实际视觉”，不把源码推断报告成视觉结论。
