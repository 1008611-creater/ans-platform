# 动效与性能规则

> 当任务明确涉及动画、过渡、微交互、展开收起、拖拽反馈、滚动动效或动画卡顿时读取。只改变业务状态、事件绑定或数据来源而不改变运动方式时不读。

## 边界

要不要做动效、做成什么节奏和手感，属于设计判断，以设计稿、项目规范或用户要求为准。本规则负责把已经确定的动效正确、流畅地实现，并守住性能。

## 先沿用项目语言

1. 复用项目已有的 duration、easing、spring 和动效组件；
2. 复用当前组件库已经处理好的进入、退出和手势能力；
3. 项目已有 Motion、Framer Motion、GSAP 或其他库时沿用同一套，不为一个效果引入第二套系统；
4. 简单 hover、active、显隐和小范围位移优先 CSS transition，不为它们增加动画依赖。

## 选择实现机制

| 场景 | 优先机制 | 原因 |
| --- | --- | --- |
| hover、active、开关、可中断状态变化 | CSS transition | 用户反向操作时可以从当前进度继续 |
| 一次性进入、提示或分段序列 | CSS keyframes 或项目已有动效组件 | 生命周期明确，不需要长期 JS 循环 |
| 拖拽、手势、物理跟随、复杂编排 | 项目已有动画库 | 需要速度、约束、取消和卸载管理 |
| 一次性进入视口 | `IntersectionObserver` 或已有封装 | 不持续监听每一帧滚动位置 |
| 滚动进度驱动 | 项目已有可靠方案或浏览器原生能力 | 避免直接用滚动事件反复读写布局 |

不要为了“更顺滑”把 CSS 可以完成的状态切换改成逐帧 JavaScript。

## 属性选择

- 连续动画优先使用 `transform` 和 `opacity`。
- 颜色、边框和阴影会触发绘制，只用于小区域、短时反馈，不在大面积表面持续动画。
- `width`、`height`、`top`、`left`、复杂 Grid/Flex 几何会触发布局。小型展开收起确实需要内容尺寸时可以使用项目已有折叠组件或一次测量方案，但不得在每帧交错读取和写入布局。
- 不使用 `transition: all`。只声明真实变化的属性，避免未来新增样式后被意外动画。
- `filter: blur()`、`backdrop-filter`、大阴影和大面积遮罩只用于小而短的表面；出现卡顿时先减少面积、模糊半径或层数，不先增加 `will-change`。

## 时长与缓动

- 时长、缓动和弹性沿用项目 Token 或设计规范，不在实现时自行设定新的视觉手感。缺少 Token 时，把本次用到的值收成变量，并在交付中说明这些值需要设计确认。
- 项目或当前组件已经支持减少动态效果时，新增明显位移或缩放必须沿用该机制，退化为等价的 `opacity` 反馈或即时最终状态；本任务不因此新建全站机制，也不扩张为无障碍审计。

## JavaScript 动效护栏

- 同一帧先完成所有布局读取，再完成写入；不要在循环中交替调用测量和样式更新。
- `requestAnimationFrame` 循环必须有明确启动、停止和卸载清理条件；组件不可见或任务结束后停止。
- 连续输入只保留最新目标，旧动画可以取消或被新动画接管，不能排队累积。
- `will-change` 只在确认首帧卡顿或即将发生复杂变换时添加，并在结束后移除；禁止 `will-change: all`。
- 动画完成回调不得成为业务状态的唯一来源。业务状态决定界面，动画只呈现状态变化。

## 滚动与布局

- 不直接在未节流的 `scroll` 事件中读取位置并同步写 React state 或样式。
- 一次性 reveal 使用观察器；必须逐帧跟随时使用项目已有封装，并确认更新不触发整棵组件树渲染。
- 动画开始和结束不应改变页面滚动位置、点击目标或稳定布局。媒体和异步内容先保留比例或尺寸，避免把布局位移误判为动画问题。
- 弹层和退出元素结束后及时卸载；卸载前不得留下透明但可点击的覆盖层。

## 验证分级

所有动效先检查：

- 动画属性是否精确声明，是否存在 `transition: all`；
- 动画过程中是否改变布局、滚动位置或控件尺寸；
- hover、active 等简单 CSS 反馈是否立即响应，反向操作时能从当前进度返回。

再按实际类型增加检查，不适用的项目不列入报告：

- 可重复或可中断交互：快速连续触发后是否到达最新最终状态；
- 进入、退出或延迟动画：取消和组件卸载后是否残留状态、计时器或透明点击层；
- 展开收起或空间变化：开始和结束是否改变滚动位置或造成意外布局位移；
- loading、disabled、selected 等业务状态动效：业务状态是否先真实成立，动画是否只负责呈现；
- 滚动驱动动效：监听、逐帧更新和组件渲染范围是否符合本文件护栏。

只有以下情况才做性能录制：用户报告卡顿；存在滚动驱动、逐帧 JavaScript、布局测量、大面积 blur/filter，或多个动画系统共同控制同一区域。录制时只回答：哪一步发生长任务、重复布局或大面积绘制，以及哪个具体属性或代码路径造成它。没有录制证据时不要声称已经解决帧率问题。
