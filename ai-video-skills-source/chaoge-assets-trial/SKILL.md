# Chaoge 多风格资产冠军

## 统一交接

开始前必须读取 `C:/Users/lsb/.codex/skills/ai-video-champion-handoff/SKILL.md`。输入必须包含 `project_state` 和已定稿剧本；输出必须更新 `project_state` 并生成唯一的 `asset_manifest`。下游只引用这份资产清单，不重复建立角色或道具编号。本节点不生成 `accepted_clip`，也不覆盖分镜、视频提示、声音、剪辑和交付。

**版本：1.4.3**

## 体验范围

本节点必须执行以下完整链路：

```text
P0 项目接收
→ P0A 十项剧本解析与全片情绪曲线图
→ P1 全片视觉风格、环境色彩策略与声音圣经
→ P2 角色母板与角色设定板
→ P2 关键道具母板
→ asset_manifest
→ 交接给 shotlist-builder
```

不得把P0A简化成资产清单，也不得跳过国家年代、世界规则、人物小传、空间链、状态链或情绪曲线。P0不是独立确认阶段，必须在同一回复中继续完成P0A；只在第10项情绪曲线图展示后统一确认。

## 硬边界

支持项目已确认的视觉类型。三维国风漫剧只是其中一种可选类型；只有 `project_state` 或已确认 P1 明确选择三维国风时，才读取 `C:/Users/lsb/.codex/skills/chinese-celestial-palace/references/visual-dna.md`、`composition-recipes.md`、`prompt-compiler.md` 与 `quality-gates.md`，且只继承空间、材质、构图和质量规则。不得因调用本 Skill 将真人实拍、二维、三维或其他已确认风格改写为另一种类型。

包内不得输出场景成图、地图、分镜草图、视频提示词、视频生成/延长/编辑、声音资产、独立音乐、连续性台账或成片复盘。角色视频试镜只由资产冠军交付人物、服装、道具、场景和候选用途规格；具体 Seedance 2.5 时间轴与视频提示词必须交由已获批准的 `sd2.5skill` 编译。关键场景只登记空间职责、视觉锚点和与道具的关系；具体镜头空间由 `shotlist-builder` 处理。任何外部图像任务都必须在用户对当次生成明确授权后，通过念念画布提交；未授权时只输出可复制提示词与待验收状态。

## 通用原则

- 只处理已定稿剧情；发现会改变资产的冲突时指出并等待拍板，不改戏、加角色、加台词或改变结局。
- 每轮只展示当前需要确认的一步。用户明确“确认、通过、定稿、继续”后才解锁下一阶段；修改时停留在当前阶段。
- 所有提示词修订从当前有效事实重新编译，不在旧稿后追加补丁。用户要求删除的内容及其否定式、解释和失效引用均不得出现在新版提示词中。
- 只引用真实存在的上传素材。生图提示词使用`{{Image 1}}`、`{{Image 2}}`；没有真实参考图时删除全部素材编号和继承措辞。
- 需要生成图像资产时，先输出对应提示词，再在已获当次明确授权后通过念念画布图像任务提交；禁止在 Skill 内直接调用供应商。任务完成后只接收念念画布登记的 `asset_id`，不以聊天附件或文件名作为正式资产。
- 用户上传结果不等于定稿，必须明确确认后才能作为下游依赖。

### 资产验收问题回报（强制可复核）

不得只写“身份不一致”“不好看”“有换脸风险”或“质感不够”。每个未通过或待确认项必须逐项写明：

1. **对照对象**：候选文件与哪一张已确认母版对照，并给出两者路径。
2. **具体部位**：脸型、眉眼、鼻口、发际线/发型、年龄感、肤色、服装、道具或三视图版式中的明确区域。
3. **可见差异**：用可观察事实描述变化，例如“母版为窄长椭圆脸，候选下颌更宽更圆”，不能只写审美形容词。
4. **下游影响**：说明会造成同一角色在视频中出现什么连续性问题，或为什么不影响使用。
5. **结论与证据**：标记“通过 / 未通过候选 / 待用户确认”，并链接视觉验收记录和真实文件。

批量生成时每个角色单独一行完成上述五项；共通的尺寸、文字和版式门只能作为共通结论，不能替代逐角色身份判断。无法从图像明确判断时必须写“待用户确认”，不得把推测写成未通过事实。

## P0与P0A

完整读取最终剧本后，按`references/story_bible.md`输出P0项目接收摘要，并在同一回复中继续完成P0A前9项。随后读取`references/emotion_curve.md`，计算第10项情绪节点；未获图像生成授权时交付文字节点表与可复制图表提示词，获授权后才通过念念画布生成16:9情绪曲线图。

第10项展示后固定询问：

```text
【请确认】以上P0A剧本解析与创作基准（含情绪曲线或节点表）是否确认？需要修改请指出具体项目。
【确认后下一步】建立P1全片视觉风格、环境色彩策略与声音圣经。
```

## P1创作基准

P0A确认后读取`references/creative_baseline.md`，先继承项目已确认的视觉类型；未确认时才提出1套完整推荐，不让用户填写空表。锁定成像或渲染介质与镜头运动语言、画幅与帧率、主光/反差/材质、环境色彩策略、全片环境声原则与音乐圣经。真人实拍与三维渲染不得混写；三维国风只在被明确选择时启用。此阶段不生成色卡图片、声音文件或音乐。

结尾固定询问：

```text
【请确认】以上P1视觉风格、环境色彩策略与声音圣经是否确认？需要修改请直接指出。
【确认后下一步】先列出9:16角色/状态母板生产清单，确认范围与依赖批次后再生成。
```

## P2角色资产

读取`references/character_assets.md`。当 P1 已确认三维国风、当前交付是纯文生图九比十六角色视觉母图且渠道为 Image2（图像生成）时，额外读取`references/image2_3d_guoman_character.md`：它取代通用单人确认稿中的真人影棚、镜头焦段和毛孔语义，使用非真人三维动画成像与反真人视觉验收门；该路线只产出视觉母图，不声称生成网格、贴图或可绑定模型。

1. 先用表格列出全部拟制作的9:16角色、怪物与必要状态，标明资产类型、上游依赖、建议批次、必要性、出图理由和当前决定；创作者确认或删改后，才形成正式生产范围。
2. 角色设定板不进入该清单，不单独立项：清单只规划9:16角色/状态母板。
3. 第1批只生成无依赖或上游基础角色的9:16单人确认稿。
4. 基础角色定稿后，才以真实确认图生成血缘亲属、变异、换装、受伤或年龄状态。
5. 所有纳入范围的9:16角色与状态确认后，直接为全部已确认角色一次性生成16:9角色设定板，不再输出第二张清单或重复询问是否立项。
6. 每个9:16依赖批次及最终整批角色设定板均需验收；全部角色资产确认后才进入关键道具。

角色阶段结束固定询问：

```text
【请确认】以上角色资产是否全部定稿？需要修改请指出具体角色和位置。
【确认后下一步】提取关键道具清单并生成关键道具母板。
```

## P2关键道具

读取`references/prop_assets.md`。先用一张无批次表格列出最终候选道具、剧情作用、识别/连续性锚点、必要性、出图理由和当前决定；创作者确认或删改后，再按已确认视觉类型编写3:4竖构图的单件资产档案照提示词。不生成三视图，不出现人物或手。

全部关键道具确认后，更新唯一 `asset_manifest`，每项登记 `asset_id`、角色/道具职责、依赖、验收状态、精确文件路径或待生成提示词、视觉质量结论。然后交接给 `shotlist-builder`；不继续越权输出分镜或视频提示。
