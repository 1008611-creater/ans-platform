# 冠军网站动效

把动效当成可验证的产品能力。先从五个权威来源发现候选，再按业务价值、品牌匹配、源码与许可、技术兼容、性能和无障碍筛选；只把通过质量门的最小代码并入当前网站。

## 权威路线

```text
页面目标与当前源码
-> 五站发现候选
-> 用户确认高影响视觉方向
-> 授权与技术预检
-> 最小范围复制或重构
-> 桌面、移动、低动态和性能验收
-> 记录真实来源与应用证据
```

本 Skill 是网站动效选型、实现合同和验收的冠军 Owner。`website-product-router` 继续拥有网站技术栈、代码交付和发布；本 Skill 不替代产品架构、品牌设计、后端或部署权限。

## 先读取所需参考

- 每次选型或比较五站时，读取 [source-catalog.md](references/source-catalog.md)。
- 准备复制、改写或集成代码时，读取 [implementation-workflow.md](references/implementation-workflow.md)。
- 判断是否足够好、是否允许进入实现时，读取 [quality-gate.md](references/quality-gate.md)。

## 固定工作流

### 1. 锁定页面工作

确认目标页面、主要用户动作、视觉主角、当前框架、既有动画库、目标设备和必须保留的品牌/业务逻辑。没有明确工作价值的动效不进入候选。

允许的工作价值只有：建立阅读顺序、解释状态变化、强化主要操作、保持空间连续性、展示真实产品能力或创造一个必要的品牌记忆点。

### 2. 按价值搜索五站

不要同时漫无目的浏览五站。根据需求选择入口：

- 整站、Hero、滚动叙事和视觉方向：先看 MotionSites。
- React 动画文字、背景、指针、卡片和实验性组件：先看 React Bits。
- 按钮、输入、开关、加载器和轻量 CSS 微交互：先看 Uiverse。
- 自定义 DOM、SVG、时间线、拖拽和滚动编排：先看 Anime.js。
- Next.js/Tailwind/Framer Motion 的 Hero、背景、Bento、视差和营销区块：先看 Aceternity UI。

最多保留三个候选。每个候选记录准确页面 URL、名称、来源类型、预览、技术依赖、许可、移动端行为和预期工作。

### 3. 让用户只参与高价值选择

以下情况必须让用户看 1–3 个可视候选后选择：Hero 主视觉、全屏背景、长滚动叙事、页面转场、品牌标志性互动，以及任何会改变首页第一印象的效果。

以下情况无需停下等待：用户已明确指定候选；修复卡顿、清理生命周期、补充 reduced-motion；不改变视觉方向的按钮反馈和状态过渡。

需要登录、购买 Pro、接受新许可或使用用户账号才能取得源码时，说明准确资源与影响并等待用户授权。不要要求用户判断框架、依赖或清理方式。

### 4. 通过硬质量门

运行 [score_motion_candidate.py](scripts/score_motion_candidate.py) 检查候选记录。任何授权不清、没有移动端/低动态替代、与当前栈冲突、重复动画/滚动 Owner、遮挡主要操作或无法清理的候选都不得实现。

### 5. 获取源码而不是复制外观

只从官方页面、官方仓库或用户已购买的官方资源复制。保留许可声明。禁止从搬运站、泄露的 Pro 提示词/模板仓库、视频画面反编译或不明代码片段获取生产源码。

MotionSites 的提示词只用于提炼结构、触发、节奏、介质和降级合同；生成结果必须按当前项目组件和设计系统重建。不得把提示词生成的整页当成已完成网站。

### 6. 最小范围集成

从当前权威源码建立隔离候选。只加入选中效果需要的组件、样式、资产和依赖；替换示例文案、图片、颜色和布局，保留当前业务组件与数据。避免引入第二个动画引擎、第二个平滑滚动 Owner或全局样式污染。

React/Next.js 动效必须标明客户端边界，清理时间线、监听器、观察器、RAF、Canvas/WebGL 和媒体资源。高频运动优先使用 `transform` 与 `opacity`。

### 7. 验收真实页面

至少验证：桌面、390px 触摸视口、键盘、`prefers-reduced-motion`、慢速媒体或静态替代、路由进入退出、重复渲染、主要 CTA 可用、控制台错误和资源清理。

测量首屏、脚本、布局、绘制、解码或 GPU 压力。效果漂亮但让页面明显变慢、产生横向溢出、掉帧、遮挡或内容不可读，视为失败并移除或降级。

### 8. 记录来源应用

在网站项目的 `source_repositories` 与 `source_application_records` 中记录：来源 URL、组件/效果名、免费或 Pro、许可、版本/提交日期、复制文件、依赖、主要改动、验证证据。只有实际改变代码且通过浏览器验收的来源才算“已使用”。

## 完成定义

只有同时满足以下条件才可完成：

- 用户需要参与的视觉选择已经确认；
- 来源、许可和源码获取路径清楚；
- 候选通过质量门；
- 代码在当前权威源码中完成最小集成；
- 真实桌面和移动路径通过；
- 低动态与失败降级可用；
- 没有破坏原有导航、业务逻辑、响应式和性能；
- 来源应用记录已写入项目权威文档。

计划、提示词、复制成功、构建通过、HTTP 200 或单张截图都不是完成证据。
