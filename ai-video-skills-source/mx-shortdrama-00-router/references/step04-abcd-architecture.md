# Step04 A/B/C/D 编译合同

用户可见路由：

```text
Step02 语义放行 -> A 镜头人物实例与证据绑定 -> B 资产与连续性合同 -> C 事件型毫秒提示词中间表示 -> D Word/Markdown/渠道交付
```

## A 实体与证据绑定

实体最小粒度是镜头人物实例，而不是全剧角色。为每个动作主语、受事者、位置、服装锚点和局部身体建立唯一 `instance_id`、中文角色引用、证据 ID、置信度和状态；同一角色跨镜头可复用资产，但同一镜头的前景男配、背景男性和局部手臂必须是不同实例。双男镜头中“条纹西装”与“深色/格纹西装”是不同实体；黑色/深色衣袖或手臂若由身份锚点闭合，绑定到对应角色。`男子`、`人物A/B`、`speaker_unknown` 不能进入生产正文；未闭合实例保持 `unresolved`，不得默认提升为男主。

身份、动作、构图、对白是不同字段，分别合并证据：Step02 身份绑定优先；Gemini 连续视频提供动作和镜头发展；Terra/GPT 只校正其可证明的起止构图和冲突；字幕/Mimo reconciliation 提供对白文本和时间，主动口型/声纹单独决定说话人。不得用整卡字符串替换覆盖冲突。

## B 资产与连续性

每个已确认人物实例只映射一个内部 `asset_id` 和一个中文显示名，未确认实例不得借用其他角色资产。场景和关键道具不能由 Step04 从构图、剧情或提示词自然语言猜出；Step02 必须以 `asset_requirements` 明确声明 `asset_id`、`kind=scene|prop`、职责、证据 ID 和适用镜头。人物、场景、道具统一建立镜头级结构化 `reference_slot`，记录参考职责、真实文件路径、SHA-256、允许实例、适用镜头和 `accepted/verified` 状态；只检查名称出现在提示词里不算资产已消费。参考图锁定脸、发型、服装、空间几何、材质和道具外形；提示词只补当前时间段新增的动作、表情、镜头、光线、声音和状态变化。

B 层资产注册表还必须提供已验收的 `generation_prompt`（或兼容字段 `image_prompt`/`prompt`）。编译器原样保存它并在 D 层渲染资产图提示词表；禁止在 D 层根据镜头剧情、服装关键词或历史资产表临时生成资产提示词。资产文件、摘要、提示词和证据缺一项即拒绝生产。

## C 提示词中间表示

每个生产组首段写一次参考协同、场景身份、环境身份和人物状态；每个小分镜保留源 `shot_id`、毫秒起止时间、构图、动作因果、镜头运动、光线/道具/环境、声音/对白、事件块和证据 ID。事件块至少记录动作主语实例、受事者实例、起始状态、变化、结束状态和时间码。台词必须在对应动作时间段，重复引用资产写 `@中文显示名`，不出现英文别名或资产 ID。

C 层不得把对白时间默认为父事件时间；每条对白必须有自己的 `timecode_ms`，并且完全落在该动作事件内。缺少起始状态、变化/动作、结束状态或独立对白时间时，C 层阻断，D 层不做任何补全。

## D 交付与质量门

Step02 的 acceptance manifest 只证明结构文件齐全，不代表语义已放行。Gemini 连续视频观察必须以 `local_start_ms/local_end_ms + continuous segment start` 回写原片时间，禁止按返回序号或模型 `shot_id` 映射 TransNet 切点；短切点先合并为可观察语义单元。每张卡的 `terra_audit.needs_targeted_recheck` 必须为 `false`，且 `verdict` 不能是 `conflict`/`uncertain`。若镜头包含硬切或主体变化，先回到 Step02 拆卡。D 只渲染 Word、Markdown、JSON 和渠道载荷，不做事实推断、角色替换或镜头计数。Word 生成前必须通过实例唯一性、双男身份分离、人物/场景/道具 reference_slot 覆盖、泛称清零、台词时间归属和参考职责覆盖检查；生成后保存合同 SHA-256 与 DOCX SHA-256 的独立渲染回执，并通过 OOXML 几何检查和 `docx-preview`/Chromium 真实截图检查。任一输入或语义门失败，停止 D 层，不交付表面完整但事实错误的文档。

## 设计不变量（S-004.4）

Step04 是纯编译器：Step02 的语义验收合同是唯一事实入口，A/B/C 只做结构化绑定和序列化，D 只读渲染。任何从服装词、身体局部、字幕姓名、旧镜头号、自由文本或历史资产表重新推断事实的实现都属于越界实现，必须删除或禁用。

进入 D 之前必须闭合两条链：语义链要求连续观察区间、`semantic_unit_ids`、镜头人物实例、动作事件、独立对白区间、说话人和冲突状态均已验收；资产链要求每个镜头实例都有唯一资产、中文显示名、真实路径、SHA-256、职责、证据和参考槽位，并且人物槽位被对应事件实际消费，场景/道具槽位被组级上下文实际消费。只出现 `@` 名称不算消费。

D 层不能重新读取原始 cards，也不能为了排版改变人物、资产、镜头数量、事件顺序或台词归属。Word、Markdown 和 JSON 必须共享同一个合同 SHA；隔离发布包还必须包含 D 层渲染器、视觉 QA 脚本及 `docx-preview/jszip` vendor，服务端优先使用包内工具，缺少工具或回读/截图 QA 不完整时必须保持 `external_blocked`。
