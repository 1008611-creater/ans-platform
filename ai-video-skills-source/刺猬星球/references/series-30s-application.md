# 刺猬星球系列化应用扩展
## 30秒一集、每集更换主角的连续剧工作法

> 证据状态：整理者推导，不是刺猬星球课程原文。
> 目的：把第66、67、79节的镜头、资产、人物—环境—行为关系，编译为适合“主角轮换、世界连续”的短剧生产字段。第78节属于成片后的声音下游，第76节只在需要特殊开场时调用。

## 一、核心判断

### 主角轮换，世界连续

这类连续剧不靠同一个主角串联，而靠以下四层连续性串联：

1. **世界连续**：时代、生活制度、空间材质、服装逻辑、光线和声音保持同一世界。
2. **锚点连续**：每集保留一个可复认的物件、地点、声音、色彩或口头习惯，不同时堆多个锚点。
3. **后果连续**：上一集留下的物件状态、传闻、交易、选择或问题，在下一集以新人物视角出现。
4. **主角变化**：每集更换主角、身份和当下任务；不强行保持同脸，也不把每集写成独立无关小品。

推荐公式：

> 新人物 + 当集小问题 + 一个可见动作链 + 一个结果/反转 + 一个世界锚点或下一集钩子。

## 二、30秒单集容量模板

以下是项目工作模板，不是课程规定的固定秒数；实际模型执行能力必须通过小样验证。

- **0—3秒：可见钩子**：先出现一个正在发生的异常、物件状态或动作，不先做空镜和世界观解释。
- **3—8秒：人物与空间落地**：只交代这个人是谁、在哪里、此刻要解决什么。
- **8—20秒：单一主动作链**：触发 → 犹豫/选择 → 执行 → 物件或关系发生变化。一个30秒集只保留一个主动作，不堆多个事件。
- **20—27秒：结果或小反转**：让人物、道具、空间或关系出现可见变化。
- **27—30秒：尾钩/锚点回收**：用一句短对白、一个声音、一个物件状态或一个新视线把观众带向下一集。

### 单集硬容量建议

- 1个主角，最多1个辅助人物。
- 1个主要地点，最多1个明确空间转移。
- 1件关键道具，必要时加1件辅助道具。
- 1条主动作链，最多1次明确反转。
- 3—5个镜头单元作为起始测试范围；不是课程硬参数。
- 台词优先采用2—4句可接话对白；信息由动作和结果承担，不用旁白解释背景。

## 三、系列前期必须先建的对象

### 1. series_bible

至少记录：

- `series_id`
- 时代与社会生活边界
- 视觉质感：光源、材质、色彩、镜头高度、景深和画面限制
- 声音基准：环境底噪、器物声、人物说话距离和是否使用音乐
- 不可改变的世界规则
- 可反复出现的地点、物件、声音或色彩锚点
- 禁止重复的主角身份和已使用人物

### 2. episode_registry

每集一行或一个对象，至少包含：

- `episode_id`
- `lead_id`：本集主角唯一编号
- `lead_identity`：身份、年龄段、任务和识别点
- `location_id`
- `key_prop_id`
- `trigger`
- `main_action_chain`
- `visible_result`
- `world_anchor`
- `previous_episode_echo`
- `next_episode_hook`
- `dialogue_lines`
- `shot_count_estimate`
- `status`

### 3. asset_manifest

每集换主角时，不需要为每个一次性人物都制作完整四视图。按风险分级：

- 一次出场、无近脸、无复杂动作：最小人物身份卡 + 一张清晰参考图即可作为起始方案。
- 有近脸、侧脸、换装、复杂动作或后续回归：使用第67节推荐的高信息量人物资产方案。
- 反复出现的地点、关键道具和色板：优先资产化，因为它们承担系列连续性。
- 每张资产都标注：是什么、保持什么、本集怎么调用、是否允许跨集复用。

## 四、主角轮换的连续性台账

不要只记录“角色是否一致”，还要记录“世界是否一致”：

| 层级 | 每集检查内容 |
|---|---|
| 主角层 | 新人物编号、身份、服装、发型、年龄段、当集任务；禁止无意复用旧主角 |
| 场景层 | 地点材质、光源方向、空间秩序、生活使用痕迹是否符合系列基准 |
| 道具层 | 关键道具初始状态、动作后状态、是否成为下一集回声 |
| 语言层 | 说话距离、句式长度、时代语气；不要每集都使用同一种金句格式 |
| 视觉层 | 色彩、镜头高度、景深和颗粒感稳定；人物脸可以变化 |
| 叙事层 | 本集结果是否改变了下一集可见的世界状态 |

## 五、连续剧提示词顺序

按以下顺序编译，不要把所有集的角色描述混在一起：

1. `系列世界基准`：只写跨集稳定的视觉、声音和生活规则。
2. `本集主角`：只写本集人物身份和最少识别点。
3. `本集场景与道具`：写人物为什么在这里、道具初始状态和使用目的。
4. `本集动作时间轴`：起始状态 → 触发 → 选择/停顿 → 主动作 → 结果 → 尾钩。
5. `镜头翻译`：先写画面目的，再写平视/俯视/仰视、机位、焦段、景别、前中后景、光线和运动原因。
6. `对白`：对白必须接住当前动作，控制在本集容量内。
7. `反向约束`：只针对本集最可能失败的身份、空间、道具、镜头和文字问题。

## 六、质感复刻的使用边界

第79节关于“生活记录场景”的结论，应迁移“生活证据优先”，不能机械迁移成手机手持、随意抖动或普通现代室内。若系列目标是宋代生活观察式影像，应保留：

- 光源方向可解释
- 空间有使用痕迹但不脏乱
- 镜头高度像真实拍摄者会采用的观察位置
- 道具与人物任务相关
- 人物和背景共享同一光线

同时由第66节决定具体镜头角度和焦段；由项目视觉基准决定是否手持、是否颗粒、是否低对比，不能把课程案例直接当成所有题材的硬规则。

## 七、单集验收清单

1. 主角是否是本集新人物，而不是旧人物换装？
2. 观众是否在前8秒内知道这个人是谁、在哪里、要做什么？
3. 是否只有一条主动作链？动作是否有触发、执行和结果？
4. 关键道具是否真的被使用，并发生可见状态变化？
5. 画面目的是否先于镜头角度？镜头高度、焦段、景别和空间关系是否能解释？
6. 人物与环境是否共享同一套光线和材质逻辑？
7. 本集是否保留一个世界锚点，但没有堆多个重复符号？
8. 结尾是否有可见结果或下一集钩子？
9. 台词是否由动作引出，是否在30秒容量内？
10. 声音是否至少有关键动作声、环境底噪和转场/收束依据？声音生成仍按第78节的成片后流程执行。
11. 本集是否更新 `episode_registry` 和资产状态，而不是只保存一段提示词？
12. 是否把“30秒模板、3—5镜头、2—4句台词”等整理者建议误写成课程硬规则？

## 八、最早生产顺序

`series_bible` → `episode_registry` → 第67节资产范围 → 第79节人物/环境/行为审查 → 第66节镜头翻译 → 单集提示词 → 30秒小样 → 画面/对白/容量验收 → 更新下一集状态 → 成片后按第78节做声音设计。

第76节只在某集确实需要非常规入画、动态遮罩或首尾帧创意时调用，不作为每集默认开场模板。
