## 账号与会话

先从当前可见页面确认域名、账号显示名、个人或企业环境、当前标签页和目标文档所有者。账号切换后必须重新确认这四项，旧页面只作为历史线索，不能作为新账号权限证据。

若用户问“这个号”“换个号”或“用这个飞书号”，以当前可见登录态为准，并把账号归属作为交付的一部分。不要读取 Cookie、Local Storage、密码、令牌或浏览器会话文件；看不到账号身份时只报告“当前账号无法从可见页面确认”。

路由图：

```text
当前可见飞书页面 -> 账号与会话识别 -> 所有者/权限回读
```

## 文档创建与保存

创建或复制文档后按这个顺序执行：确认目标账号和父空间，确认文档标题，清理新文档默认正文，写入用户授权内容，触发保存，再回读标题、所有者、一个关键章节和“已经保存到云端”或等价状态。

不要因为页面成功打开、编辑器出现或按钮点击成功就声明完成。若创建后出现默认模板内容，先检查是否需要保留；用户只要求沉淀新内容时，保留文档元数据并清理默认正文，避免示例文字混入对外文档。

交付至少包含文档链接和云端回读结果。若保存状态不可见，说明“正文已写入但云端保存状态未证实”，并继续寻找页面内保存指示或用刷新后的同一页面回读。

## 内容整理与可视化

当用户要沉淀 AI 指令、Skill 学习卡或面向他人的知识文档时，使用“先导航、后内容、再价值”的结构：

1. 顶部给出阅读导航和总路由 DAG。
2. 每个集群用一张学习卡，包含 Skill 名称、具体章节、使用场景、价值、保留或归档判断、通用提示词和真实验证标准。
3. 用表格承载重复字段，用 Mermaid 或等价文本图表达路由关系；图必须对应真实 Skill 标识和章节，不能只做装饰。
4. 面向自己和他人分别提供“怎么触发”和“为什么有价值”，避免只堆命令或项目介绍。
5. 对低价值、重复、过窄或会污染上下文的能力给出归档建议，但不未经请求删除技能或文档。

### 真实来源视觉卡

当用户要求为 GitHub 来源 Skill、官网项目或面向他人的 Skill 学习文档配图时，按以下规则生成项目来源卡。它是项目识别与学习导航，不替代 Skill 规则或真实执行验证。

1. 先判定来源：以 Skill 注册信息、上游仓库或官方站点为准。只有已核实 GitHub 仓库时才标注“GitHub · 真实仓库”；来源是官网、本地安装或无法核实时如实标注，绝不伪称 GitHub 项目。
2. 在本次任务中现场打开真实来源页面，截取完整可见首屏；截图须能看见足以识别来源的仓库名/站点名和主要内容。将原图完整嵌入卡片，使用 `contain` 等比例展示，不裁掉主要内容。
3. 不使用用户提供的参考截图、社交平台转发图、带水印图片、拼贴图或生成模型重绘图作为项目实图。参考图只可用于判断版式偏好，不能承担来源证据。
4. 卡片固定包含：Skill 名称、中文定位、来源类别与可读网址、真实页面完整截图、三条“何时有价值”的通用实践、一句话价值结论，以及“能力以本机 Skill/具体章节/真实验证为准”的边界说明。使用 `assets/project-source-card.html` 作为可复用版式基础，不把当次项目截图沉淀进 Skill。
5. 插入飞书后，截图回读卡片中的来源标签、项目画面、无水印状态和完整边界；再回读“已经保存到云端”或等价状态。任一项缺失时不宣称已完成。

适合这一卡片的最小路由：

```text
Skill 来源证据 -> 真实来源视觉卡 -> 完整项目首屏 -> 飞书插入 -> 云端回读
```

适合对外文档的路由图：

```text
用户目标 -> 集群中文名 -> Skill 名称 -> 具体章节 -> 交付物 -> 真实验证
```

用户要求“提示词”时，提示词应写成通用任务描述，并明确要求 AI 结合上下文自动补全可发现信息；只有会改变结果且无法从上下文确定的字段才提问，最多给三个选项并标注推荐项。不要要求用户手动替换大量占位符。

## 编辑与内容沉淀

编辑已有文档时先读取标题、所有者和正文边界，再决定追加、局部修改或新建副本。默认追加，除非用户明确要求覆盖指定章节。任何大段富文本粘贴后，立即回读关键标题、表格字段、链接文本和末尾位置；若关键文本不存在，视为粘贴失败。

常见修复顺序：重新定位正文编辑区，聚焦编辑器，分成小块写入，写入一块回读一块，最后检查重复标题和段落顺序。不要在无法确认光标位置时连续粘贴整篇内容。

对外文档完成前检查：没有密钥、令牌、临时签名 URL、私人聊天原文、旧账号私密链接和无关调试信息；标题、目录、链接、表格和图示可以被读者理解。

## 知识库与多维表格治理

当用户需要长期学习、筛选、复核或归档大量 Skill 时，采用双层结构，而不是把学习卡、治理字段和历史证据混在同一篇长文档中：

```text
知识库页面树：负责阅读、学习、跳转
    ├─ 总览、集群页、学习卡、路由图、归档说明
多维表格：负责治理、筛选、排序、状态与证据
    └─ 一个 Skill 一条记录，作为唯一飞书治理台账
```

1. 保留现有知识库作为可读导航层；不要为了建表重写或删除已经确认的学习卡。
2. 新建一个命名清晰的多维表格，例如 `Skill 治理台账｜路由与证据`，并在其中使用一个 `Skill注册表` 数据表和默认总览视图。
3. 最小字段为：Skill 中文名、稳定标识、所属集群、价值等级、路由状态、来源类型、真实验证、当前限制、最近复核、恢复路径。字段选项要与知识库中的颜色和状态含义保持一致。
4. 初始写入只导入已核实的基础记录；真实验证和当前限制没有证据时必须留空，不能由 AI 编造。完整 78 个主 Skill 可随后按集群逐批补齐，不一次性为了“表格完整”填充未经核实的数据。
5. 学习卡、来源视觉卡和通用提示词仍写在集群页；多维表格只保存能筛选、排序、复核和恢复的治理字段。不要把长提示词、完整截图或大段项目介绍重复塞进每一行。
6. 创建或修改后，回读表格名称、数据表名称、字段数量/字段名、至少一条记录、可见的保存状态，以及知识库目录中的入口。若其中任一项未回读，不宣称台账已可用。

适合这一结构的最小路由：

```text
现有知识库与 Skill 证据 -> 知识库与多维表格治理 -> Skill注册表 -> 集群学习页 -> 云端回读
```

## 权限与分享

查询权限时区分：当前用户是否能打开、是否能编辑、文档所有者是谁、分享范围是什么。页面可打开只证明阅读可达，不证明编辑权或分享设置成功。

创建文档和编辑用户明确指定的文档属于请求范围；改成公开、扩大分享范围、变更成员权限、转移所有权或上传敏感文件属于外部副作用。用户没有明确要求时不要执行，只报告当前可见设置或提出最小必要问题。

任何权限变化完成后回读同一对象的可见权限状态。不要输出邮箱、内部用户 ID、邀请令牌或其他不必要的身份信息。

## 云盘空间与账号信息

用户问空间时只查询当前账号对应的个人或企业存储入口，并区分总容量、已用、剩余和统计口径。不要把单个文件夹大小、浏览器页面显示的缓存数字或旧账号容量当成当前账号总空间。

若页面只能显示套餐而不能显示实时用量，明确区分“套餐上限”和“当前使用量”；若两者均不可见，不猜测是否为 100GB。交付只给用户需要的容量数字和来源页面，不输出隐私或会话数据。

## 本地文件与飞书协作

新建 DOCX、XLSX、PPTX 或报告时先按全局规则检查 OfficeCLI 配置并生成本地文件，再检查真实文件能否打开、大小和关键结构；编辑已有文件则使用对应文件 Skill。之后才执行飞书上传或导入，并单独回读云端文件名、对象位置、可打开状态和所有者。

文件链路必须拆成三段：

```text
本地生成/编辑 -> 本地文件验证 -> 飞书上传/导入 -> 云端回读
```

不要把“本地生成成功”说成“已经上传飞书”，也不要把上传按钮成功说成“云端可访问”。

## 最终回读

交付前按任务类型选择最小检查集：

- 账号任务：域名、账号归属、个人或企业环境。
- 文档任务：标题、所有者、关键章节、保存状态、链接。
- 整理任务：目录、学习卡、路由图、价值分级、对外隐私清理。
- 空间任务：总量、已用、剩余、套餐与实时口径。
- 文件任务：本地文件状态、云端文件名、位置、可打开状态。
- 权限任务：对象、当前用户能力、所有者、可见分享范围。

交付格式保持简洁，并明确“已验证”和“未验证”。任何一项只经过规划、点击或 HTTP 成功而没有页面回读，都必须标记为未验证。
