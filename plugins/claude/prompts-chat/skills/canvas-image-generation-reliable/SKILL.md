# 念念画布可靠生图

只通过正式念念画布的生图节点执行，不绕过画布改用外部图片渠道，不把“接口成功”“任务完成”当成画布完成。

## DAG（有向无环图）

```text
输入审计
  -> 节点存在且参数可保存
  -> 提交任务
  -> 任务回执/轮询
  -> 注册素材（assetId）
  -> 回写画布节点
  -> 读取素材文件
  -> 读取正式画布节点
  -> 浏览器预览验收
```

任一步失败都停在该节点，记录最早失败变量；禁止跳到下一步或用候选结果冒充正式结果。

## 固定流程

1. **输入审计**：确认项目身份、节点 ID、模型、提示词、比例和尺寸已写入节点并能重新读取。比例和尺寸必须同时存在，不能只依赖目录默认值。
2. **提交**：从画布节点创建唯一任务 ID；保存 `nodeId`、`projectId`、模型、比例、尺寸和参考资产 ID。不要重复提交同一节点，除非用户明确授权重做。
3. **回执**：轮询任务直到 `succeeded` 或明确失败；保存 `providerTaskId`、状态、输出资产 ID 和错误原因。`succeeded` 但没有 `outputAssetIds` 视为失败。
4. **素材登记**：确认每个输出 `assetId` 在画布素材索引中存在，文件路径存在且文件大小大于零；禁止只保存供应商 URL。
5. **节点回写**：将输出资产写入同一个节点的 `data.assetIds`、`data.outputAssetIds`、`data.result`、顶层 `result`、`preview`、`meta` 和状态字段，并保留可下载 URL。回写必须是原子写入并递增画布文档版本。
6. **预览验收**：重新读取正式画布文档，确认节点仍存在、状态为成功、资产 ID 和 URL 一致；再在正式画布刷新页面确认图片可见。只要出现“加载失败”或节点消失，不得登记为完成。

## 云雾 Image2 接入流程

新增或排查云雾 `gpt-image-2-c` 时，按以下顺序执行；认证只从受保护的 Agent Vault（代理凭据库）注入，绝不把密钥写入 Skill、前端或日志。

1. **提取接口契约**：确认基础地址、生成接口、编辑接口、模型名、认证头、请求超时和响应中的 `data[].url`。先做不计费的配置/连通性检查，再做一次明确授权的真实提交。
2. **编译比例与尺寸**：统一比例词典为 `9:16、16:9、1:1、4:3、3:4`；为模型声明每个支持比例对应的输出尺寸或尺寸策略、默认值和供应商实际返回尺寸。前端选项、节点持久化、服务端校验、供应商预检必须使用同一映射，不能只改下拉框。
3. **编译提示词**：把用户输入保存为节点的规范化 `prompt`，保留原文语义，统一处理空白、长度、文本编码和禁用内容；不要把提示词拼进 URL 或多层 Shell（命令行）字符串。图改图时以 multipart（多部分表单）传输图片文件，不把本地路径暴露给浏览器。
4. **封装画布节点**：节点必须有稳定 `nodeId`、`projectId`、模型、提示词、比例、尺寸、参考资产 ID 和任务 ID；生成与回写分离，节点在任务运行中不可被前端乐观删除。提交前先持久化参数，避免刷新后丢失。
5. **用户可用性**：服务端按登录用户和项目校验权限，前端只拿短期任务状态和受控下载地址；积分/计费在服务端原子扣减，失败或预检不扣费，重试不能重复扣费。不要把云雾密钥下发给用户浏览器。
6. **异步回写**：任务成功后必须依次完成“注册素材 → 写入输出资产 ID → 写入下载 URL → 更新节点状态 → 递增画布版本”。回写逻辑必须幂等，轮询超时不能把未知状态标成成功。
7. **发布验收**：同时回读服务端目录、节点运行时、前端正式静态包、模型缓存和版本查询串；在正式画布真实选择模型、输入提示词、切换比例/尺寸、提交任务并刷新页面，确认图片仍可见。只看接口回归或本地开发页不算完成。

### 已验证的卡点与防错规则

- 只改服务端模型目录会导致正式页面仍显示旧选项；必须重新构建并发布实际加载的节点静态包。
- 只让任务表记录 `succeeded` 会出现“图已生成但节点加载失败”；必须把 `outputAssetIds` 回写到节点的 `data`、`result`、`preview` 和 `meta`。
- 只显示比例而不保存尺寸会造成供应商拒绝或结果尺寸漂移；比例和尺寸必须成对校验并写入任务回执。
- 生成后直接删除节点会让异步回调失去目标；节点应保留到成功/失败终态，失败时保留原因和重试入口。
- 参考图、输出图和故事板截图职责不同；输出资产必须有独立 `assetId`，不能用参考图 URL 冒充生成结果。
- 相对下载 URL 必须由正式站点同源提供并经过登录权限校验；出现 401/403（未授权/禁止访问）时先修复会话或权限，不要重新生成。
- 发布不能只替换后端文件；必须完成“源码 → 构建包 → `main`（主分支）→ 生产静态资源 → 清缓存/改版本 → 正式画布回读”的闭环。

### 新画布节点复用模板

为每个新节点复制同一 DAG（有向无环图）：

```text
模型目录
  -> 节点参数与尺寸映射
  -> 服务端权限/计费预检
  -> 供应商请求适配器
  -> 任务表与幂等键
  -> 素材登记
  -> 节点结果回写
  -> 正式画布刷新验收
```

任何一层没有可回读证据，都只能标记为“阻塞”，不得进入可用模型目录或计费任务。

## 关键契约

- 任务完成链：`job.succeeded -> asset.registered -> node.persisted -> preview.readable`，缺一不可。
- 画布节点是唯一展示事实源；任务表和素材索引是校验源，不能替代节点回写。
- 输出回写必须幂等：同一 `jobId` 重复回调不能重复创建素材或重复追加历史记录。
- 所有写入都使用项目锁/原子替换，避免版本冲突覆盖用户正在编辑的画布。
- 参考图只作为参考输入，不得把参考图 ID 当成输出资产 ID。

## 失败诊断与修复

按顺序检查：

1. 任务表：状态、输出资产 ID、节点 ID 是否匹配。
2. 素材索引：资产记录、存储文件、权限和大小是否正常。
3. 画布文档：节点是否存在，`data`/`result`/`preview` 是否缺输出资产字段。
4. 浏览器请求：正式站点请求是否返回可读图片；未登录或权限错误不能误报为生成失败。

若任务和文件均成功、只有节点字段缺失，只对目标节点做一次安全回填：从任务表取 `outputAssetIds`，补齐上述节点字段，递增文档版本，重启或刷新缓存后重新验收。不要重新计费生成。

若素材文件不存在、任务失败或项目/节点不匹配，停止并报告最早失败变量；需要重新提交时先取得当次外部付费授权。

## 交付记录

完成时只报告：任务是否成功、输出资产是否存在、节点是否回写、正式画布是否可见、未验证项和唯一下一步。不得输出密码、令牌、Cookie、API Key 或供应商原始响应。
