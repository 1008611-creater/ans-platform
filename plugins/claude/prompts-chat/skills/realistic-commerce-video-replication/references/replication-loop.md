# Replication Loop

Use this when the task involves "复刻", "照这个感觉", "像这个但换产品", improving a failed generation, or extracting what made a reference work.

## Principle

Do not copy surface style first. Extract why the reference works:
- why the viewer stops
- why the product feels believable
- why the composition is legible
- why the light feels real
- why the proof convinces
- what should be repeated and what should be avoided

## Reference Deconstruction

For each reference image/video/previous output, create a short DNA card:

```text
Reference DNA:
Hook mechanism: <sensory shock | doubt reversal | origin contrast | process trust | gift/status | scarcity>
Proof mechanism: <what is visibly proven>
Composition: <foreground/midground/background and focal hierarchy>
Camera situation: <phone handheld | macro | table push-in | sorting table | unboxing | delivery handoff>
Light source: <specific physical source>
Reality signals: <imperfections, scale cues, hands, tools, environment>
Product memory: <what viewer remembers after 2 seconds>
Transferable: <patterns to reuse>
Do not copy: <faces, exact props, accidental text, overused pose, irrelevant brand elements>
Failure risks: <what will make the new version fake or boring>
```

## Replication Modes

**Structural replication**
- Keep hook, proof sequence, shot purpose, and visual hierarchy.
- Change product, location, props, and brand surfaces.
- Use for most commerce assets.

**Sensory replication**
- Keep the same kind of burst point: peel, crack, pour, steam, crunch, juice, fiber, texture reveal.
- Change the physical evidence to match the new product.
- Use for food, fruit, drinks, beauty, handmade goods.

**Trust replication**
- Keep process beats: sorting, checking, packing, handoff, usage proof.
- Make the process realistic for the product category.
- Use when buyer skepticism is about authenticity, freshness, durability, origin, or delivery.

**Composition replication**
- Keep foreground/midground/background relationship and camera distance.
- Change subject matter.
- Use when the reference has strong visual design but weak product transfer.

## Anti-Copy Rules

Never blindly copy:
- exact person identity, face, or pose unless the user owns/requests identity preservation
- random text, watermarks, UI, pricing, or labels
- decorative objects that do not support proof
- lighting that was attractive but physically unmotivated
- luxury styling that makes the product less believable
- "logo as main event" if the reference worked because of product evidence

## Improvement From Failed Outputs

When a generated image fails, write a failure card before rerolling:

```text
Failure card:
Failed gate: <reality | naturalness | composition | hook/proof | light | text>
Visible symptom: <what is wrong on screen>
Likely prompt cause: <too many requirements | vague light | overemphasis on logo | no real action | missing scale cue>
Single reroll move: <one targeted change>
Keep: <what already works>
```

Only change one main cause at a time. This creates a reusable learning trail instead of random rerolls.

## Compounding Habit

For project work, save:
- prompt set
- accepted outputs
- rejected-output notes when possible
- contact sheet
- final DNA card

If the same failure pattern appears across projects, update this skill or a project style guide with the general rule. Do not add one-off product details to the skill.
