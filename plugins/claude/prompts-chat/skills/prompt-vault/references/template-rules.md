# 提示词模板规范与复利规则

## 核心理念

模板是提示词的复利机制。一条好用的提示词提炼成模板后，后续每次使用都在已有经验上叠加，减少从零开始的工作量。

## 模板层级

```
基础模板（_template.md）
  ├── 所有提示词共有的最小字段集
  └── 分类模板（_template_<分类>.md）
      ├── 该分类特有的字段和结构
      └── 适配规则（什么情况用、哪些必填、怎么填）
```

## 基础模板字段（所有提示词必须有）

| 字段 | 必填 | 说明 |
|---|---|---|
| 标题 | 是 | 一级标题，写明提示词名称 |
| 用途 | 是 | 这条提示词解决什么问题，什么场景用 |
| 适用模型/渠道 | 是 | 在哪个模型/平台/渠道上用 |
| 效果备注 | 是 | 实际效果如何，踩过什么坑，好不好用 |
| 使用日期 | 是 | 首次使用时间 |
| 提示词正文 | 是 | 完整提示词内容，可直接复制使用 |
| 示例输出 | 否 | 贴一次实际生成结果，方便回溯效果 |

## 分类模板

### 1. Seedance 2.5 视频模板（_template_sd25.md）

额外字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 参考图职责 | 是 | 每张 @图片 参考什么/不参考什么 |
| 全局连续性约束 | 是 | 建筑、角色、光线、道具的连续性锁定 |
| 场景与人物事实 | 是 | 场景身份、环境、人物任务、道具初始状态 |
| 动作段 | 是 | 按因果链：起始→触发→反应→主动作→结果→微反应→尾钩 |
| 镜头状态 | 是 | 静态/动态，写明机位、运动路径、停止点 |
| 对白与声音 | 是 | 角色、台词、音色、语速、停顿、口型同步 |
| 现场声 | 是 | 环境声描述，无字幕/无BGM声明 |
| 局部硬约束 | 是 | 禁止项清单（换脸/滑步/穿模/建筑变形等） |

适配规则：
- 触发条件：用户要 Seedance 2.5 图生视频/文生视频时
- 必须先确认：画幅（9:16/16:9/1:1）、时长、参考图数量
- 动作段不写秒数/时间戳/帧号
- 每段只保留一个主动作
- 台词逐字锁定，不省略不改写

### 2. AI 图片生成模板（_template_image_gen.md）

额外字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 画幅与尺寸 | 是 | 如 9:16 1024x1536、1:1 1024x1024 |
| 构图原型 | 是 | 主体的空间位置和视觉路径 |
| 主奇观 | 是 | 画面的核心视觉焦点，只允许一个 |
| 光线方向 | 是 | 主光来源、冷暖关系 |
| 色彩预算 | 是 | 基底色 + 局部强调色 |
| 材质证据 | 是 | 皮肤/布料/金属/皮革的反射反应 |
| 参考图策略 | 否 | 垫图/sref/ cref 等参考图使用方式 |
| 负面约束 | 是 | --no 或文字描述的禁止项 |

适配规则：
- 触发条件：用户要 AI 生成图片时
- 必须先确认：出图渠道（Midjourney/OpenLux/其他）、画幅、主体类型
- 一个主奇观，不堆砌
- 尺度证据至少四类（台阶/柱列/人物/开间等）

### 3. AI 视频通用模板（_template_ai_video.md）

额外字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 视频模式 | 是 | 文生视频/图生视频/首帧生视频 |
| 画幅 | 是 | 9:16/16:9/1:1 |
| 时长 | 是 | 总时长和段数 |
| 运镜设计 | 是 | 每段主运镜、机位、速度 |
| 转场方式 | 是 | 硬切/一镜到底/遮挡揭示 |
| 声音设计 | 是 | 配乐类型、环境声、对白要求 |

适配规则：
- 触发条件：用户要 AI 视频但不是 Seedance 2.5 时
- 每段只有一个主运镜
- 人物存在时必须有可见主动作，不能用"静立/呼吸"替代

### 4. 日常工作模板（_template_general.md）

额外字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 角色 | 是 | AI 扮演什么角色（审查者/助手/分析师等） |
| 输入要求 | 是 | 需要提供什么输入（代码/文档/数据等） |
| 输出格式 | 是 | 期望的输出结构（清单/报告/代码等） |
| 约束条件 | 否 | 特殊限制（长度/语言/风格等） |

适配规则：
- 触发条件：日常工作中需要 AI 帮忙时（代码审查、文档撰写、分析等）
- 角色定义要具体，不写"你是助手"，写"你是资深后端架构师"

## 复利规则：从提示词提炼模板

当一条提示词使用次数 ≥ 3 次且评分 ≥ A 时，触发提炼流程：

1. **识别可复用结构**：哪些部分每次都不变（角色定义、输出格式、约束条件）
2. **提取变量**：哪些部分每次都变（用 `{变量名}` 占位）
3. **写适配说明**：什么场景用这个模板、哪些变量必填
4. **存为模板**：保存到对应分类目录，文件名 `_template_<细分>.md`
5. **更新索引**：运行 `python scripts/prompt_vault.py scan` 更新模板统计

提炼示例：
```
原提示词："你是一位资深后端架构师，审查这段 Next.js API 路由的安全性..."
可变部分：具体代码、审查重点
不变部分：角色定义、输出格式（评分卡+改进建议）

提炼为模板：
角色：资深后端架构师
输入：{代码} {审查重点}
输出：安全性评分卡 + 逐项改进建议
约束：不改写代码，只提建议
```

## 模板迭代规则

- 模板用过 5 次后发现字段不够用 → 补充字段并标记版本号
- 模板用过 10 次后发现可以拆分 → 拆成更细的子模板
- 模板的模板（元模板）不实际使用，只用于生成新模板
- 每次提炼后记录提炼来源（哪条提示词、哪次使用）
