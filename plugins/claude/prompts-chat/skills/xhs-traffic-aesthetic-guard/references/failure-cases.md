# Failure Cases And Blockers

## Case 1: AI self-explaining lines

Reject visible lines like:

- `第二张只负责收藏`
- `第三张只展示报告效果`
- `家长要看这种图`
- `这才像诊断图`
- `边界先放前面`

Why:

- real creators do not talk like this on image cards
- it reads like AI explaining its own layout
- it turns a traffic note into a manual

## Case 2: Public-facing disclaimer leakage

Do not put these on public note images:

- `不包录取`
- `不收证件号`
- `不替代官方系统`
- `只做初筛`

Move them to:

- private reply
- comment follow-up
- pre-sale explanation

## Case 3: Count mismatch

Examples:

- image says `8项` but shows 12 items
- image says `4栏` but the layout is not 4 real fields

This breaks trust immediately.

## Case 4: PPT information card

Symptoms:

- too many explanation lines
- image cards full of long sentences
- consulting deck feel instead of native note feel

Preferred replacement:

- image 1 for click
- image 2 for save
- image 3 for result

## Case 5: Text sounds like AI, not a person

Symptoms:

- sentences too complete
- designer-intent narration
- tutorial voice
- product manager voice
- customer-service voice

Better direction:

- `先看位次`
- `先填这8项`
- `别先收藏学校`
- `很多人第一步就错了`

## Case 6: Zero-view panic publishing

Reject recovery drafts that try to fix 0 views by:

- immediately reposting a near-duplicate gaokao note
- turning the next note into a stronger sales pitch
- adding more public disclaimers to prove compliance
- using a six-card service deck after a low-distribution post
- editing the same weak post repeatedly without checking indexing

Why:

- 0 views may be a chain/indexing problem, not just a content problem
- repeated similar posts can deepen the wrong account label
- stronger service language often looks more commercial, not more clickable

Better direction:

- first verify public visibility and search indexing
- next post can be a non-commercial life-like gaokao parent mistake
- use 5 cards only: click, conflict, checklist, half-filled proof, one keyword
