## 二、收集方法（三步，全部自动）

### 第 1 步：抽取会话需求
逐个读取会话文件的元信息与用户发言，丢掉系统模板（AGENTS.md 注入、环境说明、探针测试），
只保留你本人写的真实需求。按「时间 / 工作目录 / 需求原文」输出。

- 已完成，产出：`raw/codex-sessions.json`（134 条）、`raw/claude-sessions.json`（46 条）
- 注意：正在运行的会话文件会被占用，读取失败自动跳过，不影响结果

### 第 2 步：抽取代码提交
遍历所有仓库，取首次提交、末次提交、提交总数，按月聚合，识别「哪个月在集中做哪个项目」。

- 已完成，产出：`raw/git-inventory.json`（128 个仓库）

### 第 3 步：合并成时间线
把上面两路数据按时间对齐，同一项目合并成一条，补上：
- 项目名与一句话定位（从 README / AGENTS.md 首段取）
- 我做了什么（从会话需求归纳）
- 可量化成果（提交数、代码行数、域名、用户数、金额——只写有出处的）
- 素材位置（截图、视频、线上链接的真实路径）

产出：`内容时间线.md`

## 三、需要你做的（只有两件事）

1. **确认哪些能公开**。有些项目涉及客户、付费、私人数据（财务分析、矿泉水 API、算命盘），
   要你决定是写进去、脱敏写、还是完全不提。
2. **补充机器查不到的**。比如：比赛名次、获奖、合作方名称、实际收入、用户反馈截图。
   这些只存在于你的记忆或对话里，我会列一份「待你确认」清单逐个问你。

## 四、边界说明

- 不编造。任何一条没有文件/提交/线上地址支撑的内容都不会进清单。
