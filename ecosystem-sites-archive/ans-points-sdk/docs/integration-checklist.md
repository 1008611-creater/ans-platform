# 项目接入核对

这些是接入实现条件；本仓库不声称你的部署已经满足。

## 订单与身份

- 使用项目已有服务端登录会话；客户端不能传任意本地用户/ANS 用户来扣款或领取权益。
- 发请求前持久化购买 reference、归属本地用户、商品、发布档次、预期价格、固定返回 URL。
- reference 在同项目中唯一，8–80 个字母、数字、下划线或短横线。重试原单保持 body 完全一致。
- 保存结算单 ID 和首次成功回执的订单 ID、ANS 账号绑定，数据库唯一约束防止重复授权。
- 原始商户接入凭据只在服务端环境保存；轮换后旧凭据失效，查询旧单使用新凭据。

## 回执与权益

- 不信任浏览器回跳参数、截图、客户端余额或已支付字样。
- 从 ANS 固定 HTTPS API 查询；逐一比对本地记录，不只查看 paidAt。
- 仅 `paid` 且 `entitlementActive === true` 才开通本次购买的权益。
- 争议/退款及时暂停本次购买权益，避免错误收回同用户其他合法购买的权益。
- 当前无 webhook：通过受保护功能访问或后台任务查询，查询不确定时停止新授权。
- SDK/外部接口并不自动执行你的项目实际交付；交付、售后与许可仍按你公开的真实商品约定完成。

## 生产存储与恢复

- 用自己的事务数据库替换 HTTP 示例里的内存 Map。
- 不确定结果保留原单，不生成新 reference；已知 ID 先查回执，未知 ID 用原 body 恢复创建。
- 当价格/档次发布更新时，旧购买按原回执固定版本核对；新购买使用新的本地订单快照。
- HTTPS 返回来源必须事先在 ANS 商品接入设置登记，禁止开放重定向；返回URL最多1000字符，不含用户名、密码或fragment。档次ID限制1–60位字母、数字、下划线或短横线。
- 商品凭据格式为ansm_后43位字母、数字、下划线或短横线。表单跳转使用固定ANS来源；示例CSP仅允许本来源与https://ans.cauai.fun。
- 用无敏感信息的 requestId 与服务端错误码定位问题，不记录鉴权、原始响应、个人信息或带私密 query 的 URL。
- 对自己的创建/领取接口落实同源与 CSRF 校验；不要直接复用示例的演示会话作为生产认证。
